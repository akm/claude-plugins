# pr-teeth

自分にレビュー依頼が来ている GitHub の PR を巡回し、硬くてとっつきにくい部分を
噛み砕いて解説する Claude Code プラグインです。

名前の由来は、コンテキスト依存が強く技術スラングの多い PR を、歯で噛み砕くように
飲み込める形にほぐすというコンセプトから。噛み砕いて理解できた語は「栄養」として
用語集に蓄積されます。

**読み取り専用です。** GitHub へのコメント・承認・マージ等の書き込みは一切行いません
(レビューはユーザー自身が行うため)。

## できること

- `is:pr review-requested:@me state:open archived:false` に該当する PR を全件解説する
- 番号や URL で**指定した PR** を解説する(マージ済み・クローズ済みも読める)
- リポジトリごとに設定した**レビュー範囲**(必須/推奨/対象外)に照らし、該当を示して並べる
- 文脈依存の語を、ブランチを実際にチェックアウトして**ソース上で裏取り**してから説明する
- 説明した語を**用語集**に蓄積し、理解が進むにつれて説明を減らす
- 結果を**単一の自己完結 HTML**として出力する(必要なら Mermaid の図つき)

## コマンド

| コマンド | 用途 |
| --- | --- |
| `/pr-teeth` | レビュー依頼 PR を巡回して解説する |
| `/pr-teeth-pick` | **番号や URL で指定した** PR を解説する (マージ済みも可) |
| `/pr-glossary` | 用語ポートフォリオの表示・ステータス変更 |

`/pr-teeth` の引数:

- `mode=full`(既定) … 現在オープンの依頼を全件
- `mode=changes-only` … 新規・更新分のみ(定期実行向け)
- `lang=<言語タグ>` … その実行だけ出力言語を上書き

### 指定した PR を読む (`/pr-teeth-pick`)

`/pr-teeth` は「レビュー待ちを消化する」ためのもので、対象はオープンな依頼に
限られます。次のような**目的の違う**読み方には `/pr-teeth-pick` を使います。

- マージ済み PR を後から読んで**学習する**(レビューではなく理解のため)
- レビューし損ねた PR を**振り返る**

PR は番号でも URL でも指定でき、複数まとめて渡せます(1ページにまとまります)。

```
/pr-teeth-pick owner/repo#123 https://github.com/owner/repo/pull/456
```

巡回との違いは**対象の決め方だけ**で、噛み砕き方・用語集・HTML 出力は共通です。

| | `/pr-teeth` | `/pr-teeth-pick` |
| --- | --- | --- |
| 対象 | レビュー依頼が来ているオープンな PR | 指定された PR (open/closed 問わず) |
| 「前回からの変更」 | 更新された PR で出す | 出さない (毎回全体を解説) |
| レビュー範囲の表示 | 必須 / 推奨 / 対象外 | 重点 / 参考 / 周辺 |
| 用語集 | 蓄積する | 同じように蓄積する |

マージ済みの PR に「レビュー必須」と出るのは意味がずれる(レビューはもう終わって
います)ため、番号指定では**読み方の指標**として文言を変えています。分類そのものは
大きい PR でどこから読むべきかの手がかりになるので残しています。**内部の分類は
同じ**で、変わるのは表示だけです。

なお `/pr-teeth-pick` は `state.json` を読み書きしません。あれは巡回時の通知の
重複抑制用で、指定した PR を解説することとは無関係だからです。

### 一度説明した PR が更新されたとき

`mode=full`(手で `/pr-teeth` を呼んだとき)は、更新の有無にかかわらず毎回全件を
解説し直します。

`mode=changes-only` では、前回の記録と比べて**新規または更新の PR だけ**が対象に
なります。更新の判定は次のどちらかが変わったときです。

- head SHA が変わった (コミットが積まれた)
- `updatedAt` が変わった (**PR 本文の書き直し、レビューコメントの追加**、
  ラベルやベースブランチの変更など)

コミットを伴わない更新も拾うため、レビューを受けて本文が補足された場合にも気づけます。

更新された PR の解説には、冒頭に**「前回からの変更」**が付きます。前回の SHA からの
コード差分を中心に何が変わったかを示し、そのうえで全体の解説が続きます
(時間が空くと前回の内容を覚えていないため、差分だけでは読めないため)。

なお**本文そのものの差分表示は未対応**です。本文が変わったことは検知して解説を
作り直しますが、「本文のどこが変わったか」は示しません
([#11](https://github.com/akm/claude-plugins/issues/11))。

## 導入

1. マーケットプレイスを登録する。

   ```bash
   claude plugin marketplace add akm/claude-plugins
   ```

2. プラグインをインストールする。

   ```bash
   claude plugin install pr-teeth
   ```

または `settings.json` に直接書く。

```json
{
  "extraKnownMarketplaces": {
    "akm-claude-plugins": {
      "source": {
        "source": "github",
        "repo": "akm/claude-plugins"
      }
    }
  },
  "enabledPlugins": {
    "pr-teeth@akm-claude-plugins": true
  }
}
```

`settings.json` の詳しい説明については [公式ドキュメント](https://code.claude.com/docs/en/settings#plugin-settings) を参照してください。

インストール後、次の「準備」で GitHub トークンを設定すれば使えます。

## 前提

- `python3` (3.11 以降) が PATH にあること。設定の読み込みに標準ライブラリの `tomllib` を使います。
- `gh` (GitHub CLI) があること。無い場合は `curl` で REST API を直接叩きます。
- `git` が使えること (PR のブランチをチェックアウトして中身を確認するため)。

## 準備

### 1. GitHub トークン

`review-requested:@me` はトークン所有者本人としての認証が必要です。**読み取り専用**の
PAT を用意してください。

- Fine-grained: `Contents: Read-only`, `Pull requests: Read-only`, `Metadata: Read-only`
- fine-grained で検索が空振りする場合は `repo` (read 相当) の classic token

次の順で探します。

| 順 | 探す場所 | 備考 |
| --- | --- | --- |
| 1 | 環境変数 `GITHUB_TOKEN` | 値をそのまま使う |
| 2 | 環境変数 `GITHUB_TOKEN_FILE` | トークンを書いたファイルのパス |
| 3 | `gh auth token` | `gh auth login` 済みならこれで足ります |

いずれも取得できなければ、その旨だけ通知して終了します。
取得したトークンは前後の改行・空白を落としてから使うため、ファイルの末尾改行は気にしなくて構いません。

`GITHUB_TOKEN_FILE` を指定したのに読めない場合は、理由を添えて知らせます (設定ミスを黙って
握りつぶさないため)。その場合も後続の `gh auth token` は試します。

**トークンを設定ディレクトリに置く経路は用意していません。** 設定に秘密情報が混ざると、
バックアップや同期の対象にしたときに漏れるためです。ファイルで渡したい場合は
`GITHUB_TOKEN_FILE` で任意の場所を指してください。

トークンの値がログ・生成物・通知に出ることはありません (表示されるのは入手元だけです)。

### 2. 設定ファイル

設定ディレクトリは次の場所です。

```
$HOME/config/github.com/akm/claude-plugins/pr-teeth/
```

環境変数 `PR_TEETH_CONFIG_DIR` を設定すると、その場所を優先します。

この配下の `repos/` には、PR を読むための作業リポジトリが置かれます。
**取得は部分クローン (`--filter=blob:none`) で、保持は「最終利用から30日」
「20件」「合計5GiB」で頭打ち**になり、超えた分は古い順に自動で削除されます。
手動で確認・掃除する場合は次を実行します。

```bash
python3 "<プラグインのパス>/scripts/pr_teeth.py" repo-cleanup
```

設定が無くても既定値で動きます(出力言語は日本語)。
**この中にトークンは置きません**(上記のとおり環境変数で渡します)。秘密情報を含まないため、
設定ごと同期・共有しても資格情報が漏れることはありません。

## 出力言語

設定は `config.toml` 1枚です。ユーザー全体の既定を最上位に書きます。

```toml
language = "ja"       # BCP 47 の言語タグ (ja, en, ko, zh-Hant ...)
```

リポジトリごとに変えたい場合は同じファイルの `[repos."owner/repo"]` で上書きします。
社内リポジトリは日本語、OSS は英語、といった使い分けができます。

優先度は次のとおりです(高い順)。

1. 実行時引数 `lang=`
2. `[repos."<owner>/<repo>"]` の `language`
3. 最上位の `language`
4. 既定 `ja`

解説本文・見出し・用語解説・通知は、解決された言語で出力されます。

## レビュー範囲の設定

リポジトリごとに、自分が見るべき範囲を glob で設定します (同じ `config.toml`)。

```toml
# リポジトリ別設定の既定値
[repo_defaults]
unmatched = "should_review"   # どの範囲にも一致しない変更の既定分類

[repos."owner/service-api"]
must_review   = ["src/payments/**", "src/auth/**"]  # レビュー必須
should_review = ["src/api/**"]                      # 見たほうが良い
ignore        = ["docs/**", "**/*.md"]              # 見なくてよい

[repos."someorg/oss-library"]
language      = "en"          # このリポジトリの PR だけ英語で解説する
should_review = ["src/**"]
```

リポジトリ名は `/` を含むため、テーブル名を `[repos."owner/repo"]` と引用符で囲みます。

- 1ファイルが複数範囲に一致したら **必須 > 推奨 > 対象外** で最上位を採ります
  (重要な範囲を `ignore` で誤って隠さないため)。
- 未設定のリポジトリは全ファイルを推奨扱いにします(安全側)。
- PR は必須 → 推奨 → 対象外の順に並び、対象外のみの PR は1行に畳まれます。
- 深掘りと用語の裏取りは、必須・推奨の範囲を中心に行われます。

## 用語集

説明が必要な語は使い込むほど理解が増え、いずれ説明不要になります。これをユーザー単位で
管理し、ステータスに応じて説明の厚みを変えます。

| ステータス | 挙動 | 昇格 |
| --- | --- | --- |
| `new` | フルで説明 | 初出時に自動登録 |
| `learning` | 1〜2行の軽い再掲 | 通算3回の出現で自動 |
| `known` | **説明を省略** | **ユーザーの確認が必要** |

`known` への昇格だけは人の確認を挟みます。推定だけで確定すると、偽陽性で説明が
勝手に消えてしまうためです。会話から理解の兆候が見えた場合、Claude は昇格を
**提案**しますが、承認を得るまで確定しません。

**ステータスと出現回数は言語をまたいで共有されます。** 日本語で理解済みにした語は、
英語で出力したときも説明が省かれます(理解しているかどうかは出力言語に依らないため)。
説明文だけが言語ごとに保存されます。

## ファイル一覧

設定ディレクトリの中身です。

| ファイル | 役割 | 編集 |
| --- | --- | --- |
| `config.toml` | 設定一式(出力言語・リポジトリ別のレビュー範囲と言語) | ユーザー |
| `glossary.json` | 用語集 | skill と `/pr-glossary` |
| `state.json` | 通知済みの記録 (`mode=changes-only` 用) | skill |
| `out/` | 生成された HTML の置き場所 | skill |

生成物は `out/` の下に出ます。作業中のリポジトリに散らからないよう、出力先を
相対パスで指定した場合もここに解決されます(絶対パスを指定したときはその場所)。

### 生成される HTML について

CSS と JS はインラインで、単一ファイルで完結します。**図がなければ外部への
アクセスは一切ありません。**

図 (Mermaid) を含む場合だけ、描画ライブラリを CDN (cdnjs) から読み込みます。
ライブラリが 3.2MB あり、図は補助でしかない (単純な場合は省略される) ため、
PR ごとに埋め込むのは割に合わないという判断です。

- 改竄検知のため `integrity` (SRI) を付けています。CDN が別の内容を返した場合、
  ブラウザがスクリプトを拒否します。
- **読み込めない場合 (オフライン・CDN 障害・SRI 不一致) でも本文は読めます。**
  図は Mermaid のコードがそのまま表示される形にフォールバックします。

## fork する場合

設定ディレクトリの場所は、`scripts/prteeth/config.py` の `PLUGIN_SOURCE` に
リテラルで書かれています (`github.com/akm/claude-plugins`)。fork して別の
マーケットプレイスから配布する場合は、**この 1 箇所だけ**を書き換えてください。

```python
PLUGIN_SOURCE = "github.com/akm/claude-plugins"   # ← fork 時はここだけ
```

実行時に配布元を推定する方法は採っていません。`${CLAUDE_PLUGIN_ROOT}` はインストール先
しか返さず、そこから配布元を辿る経路 (`known_marketplaces.json` やキャッシュのパス構造) は
いずれも非公式で、変わると設定と用語集を見失うためです。
