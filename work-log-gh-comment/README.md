# work-log-gh-comment

実行したコマンドとその出力を、**機密を伏せたうえで省略せずに** GitHub の Issue / PR へ記録する skill を配布するプラグインです。

実環境を変更する作業や、後から経緯を追う必要がある作業で、後から読む人 (未来の自分を含む) が何が起きたかを実際の出力で確認できるようにします。

## 収録スキル

| スキル | 説明 |
| --- | --- |
| `work-log-gh-comment` | 作業ログを Issue / PR のコメントとして投稿する |

## 2 つの原則

記録は 2 つの原則に従い、**この順で優先します。**

1. **機密は貼らない。** Issue と PR のコメントは全世界から読め、編集しても履歴が残り、回収できません。
2. **それ以外は省略も要約もしない。** 出力のどの部分が後で役に立つかは、記録する時点では分かりません。

順序が要点です。「省略しない」を先に立てると、機密が「例外」の位置に置かれ、気づかなかったときに漏れます。**先に貼らないものを決め、残りを全部貼る。**

機密の判定は**コマンドを実行する前**に行います。出力を見てから気づく形では、見落としたときに何も働かないためです。

## 何が保証されるか

- **失敗したコマンドと、人間に代行を依頼したコマンドを省かない。** 試行錯誤の経路そのものが、次に同じ作業をする人への情報になります。
- **出力の中の食い違いを、解釈で均さない。** 「サマリは `3 errors` なのに `ERROR` 行が 2 行しかない」「終了コードは 0 なのに本文は失敗している」— こうした矛盾は、要約すると消えます。
- **部分マスクをしない。** 末尾 4 桁や接頭辞を残す書き方は、残したぶんを漏えいに数えます。
- **機密でない値まで伏せない。** 全部隠すと、記録は「何かを実行した」以上のことを伝えなくなります。

## 明示的な依頼でだけ動く

**通常の作業では発動しません。** 「作業ログを Issue に記録して」「実行内容を PR にコメントして」のように依頼したときだけ起動し、引数で記録先の番号を指定します。

## 同梱の評価 (evals)

`skills/work-log-gh-comment/evals/` に、スキルを変更したときに効果を測るための一式が入っています。

- `evals.json` — 6 つのテストケース。Alert の使い分けと機密の扱いが分かれるように選んであります
- `fixtures/` — テストで実行するスクリプト (外部サービスにはアクセスしません)
- `grade.py` — 出力を機械的に採点します
- `test_grade.py` — 採点そのもののテスト (80 件)

判定器は 6 つの eval すべての結論を左右する単一障害点のため、判定を足すときは**先に `test_grade.py` へ反例を書き、Red を見てから** `grade.py` を直します。

```sh
make -C skills/work-log-gh-comment/evals test
```

python3 と make だけで動きます。

## 文中の例について

`references/format.md` と `references/sensitive-data.md` の例は、lappds という配信基盤の実際の作業記録から採っています。**コマンドやリソース名はその題材のものなので、形と使い分けだけを読んでください。**

抽象的な例に置き換えていないのは、実際の出力にしか現れない食い違いこそが、この書式の扱う対象だからです。

## 使い方

インストール手順は [リポジトリの README](../README.md#使い方) を参照してください。

```bash
claude plugin marketplace add akm/claude-plugins
claude plugin install work-log-gh-comment@akm-claude-plugins
```

`gh` コマンドが認証済みであることが前提です。
