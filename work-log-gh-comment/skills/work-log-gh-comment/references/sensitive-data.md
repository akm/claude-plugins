# 機密の扱い

**機密は貼らない。これは「省略しない」より優先する原則。** 省略しないのは、後から読む人のため。機密を貼ると、読む相手が全世界に広がる。Issue と PR のコメントは、編集しても履歴が残り、回収できない。

## いつ気づくか — 出力を見る前に決まる

**機密の判定は、出力を見てからではなく、コマンドを実行する前に行う。** 「機密に気づけたかどうか」を条件にすると、気づけなかったときに何も働かない。出力を見て判断する形だと、見落としたときに確認も飛ばしてしまう。コマンドは実行前に分かる。

**次のコマンドは機密を出す。1 つでも実行する作業は、投稿の前にユーザーに確認する。**

- **そのプロジェクトの CLI のうち、トークンや資格情報を発行・再発行するもの** (lappds では `lappds-cli site register` / `site rotate-secrets`)
- `gcloud secrets versions access` / `kubectl get secret` — 機密の値そのものを出す
- `cat` / `grep` の対象が `.env`・鍵ファイル・トークンを含む JSON

**この列挙は代表例で、すべてではない。** 初めて使うコマンドは「これは秘密の値を表示するためのものか」を実行前に自問する。

## 何を伏せるか

**次の種類の値は伏せる。ただしこれも代表例で、列挙がすべてではない。**

- 登録トークン・認証トークン (`enroll-*.json` の中身)
- パスワード (`db_password`)
- API キー・Webhook URL (Slack の incoming webhook など)
- `.env` の中身、`kubectl get secret -o yaml` のようなダンプ

**上に当てはまらなくても、それを知った人が何かをできてしまう値は伏せる。** 内部 IP、社内システムの URL、個人名、鍵の断片。**迷ったら伏せる** — 省略の判断と同じで、難しいと感じた時点で安全なほうを選ぶ。

**リポジトリの `.gitignore` が保護している値は、ここでも伏せる。** 平文のトークンを含むファイルは、たいてい `.gitignore` で除外されている。**コミットしないものを、コメントで外へ出さない。** `.gitignore` は、そのリポジトリが何を機密と考えているかの手がかりになる。

## どう伏せるか

**値は全部消す。一部を残さない。** 機密の行だけを伏せ、同じ出力の非機密の行はそのまま残す。次は lappds での実例 (`lappds-cli` は拠点に配る登録トークンを発行するコマンド)。

```
$ lappds-cli site enroll-token --site-id site-9f3c2a1b
以下の ENROLLMENT_TOKEN をオペレータへ安全に渡してください
ENROLLMENT_TOKEN=(マスク。平文のトークンなので貼らない)
DEVICE_ID=dev-4d5e6f70
チャネル=stable
LFDS_ENROLLMENT_TOKEN=(マスク。平文のトークンなので貼らない)
有効期限: 2026-09-04 09:00:00
```

伏せたのはトークンの 2 行だけで、`DEVICE_ID`・`チャネル`・`有効期限` は残っている。**これらは知っても何もできない値なので、伏せると記録の価値だけが減る** (下の「機密でない値まで伏せない」)。

**末尾 4 桁や接頭辞を残す部分マスクをしない。** 断片でも推測の手がかりになり、長さや文字種の情報も漏れる。`xxx_enr_****` のように接頭辞を残す書き方は、残したぶんを漏えいに数える。

**伏せた値をどう入手するかを地の文に書く。** 読む人はその値が要って記録を見に来る。「再発行するには `site register` からやり直す」「実行時のログにのみ残る」のように、次の行き先を示す。

**マスクではなく「省略」と書かない。** 省略は貼らずに済ませた箇所に使う語で、マスクは貼ったうえで値だけを消したもの。混ぜると読む人が判断を誤る (省略してよい場合は SKILL.md の「省略してよい 2 つの例外」が定める)。

**機密でない値まで伏せない。** 拠点 ID・有効期限・ファイル名のような、それを知っても何もできない値は、記録として残す価値のほうが大きい。全部隠すと、記録は「何かを実行した」以上のことを伝えなくなる。伏せるのは、知った人が何かをできてしまう値だけ。

## 投稿前の確認

記録のためのコメントは、リポジトリを変えないので本来ユーザーの確認を要さない。**機密の判断だけは別。** 上の「いつ気づくか」に該当するコマンドを 1 つでも実行した作業は、マスクを施した本文を用意したうえで、投稿の前にユーザーに確認する。
