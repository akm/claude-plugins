# doc-structured:refs: ある ID を参照している箇所を探す

手書きの Markdown から、ある ID とその子孫の ID (渡した ID の後ろに `-<記号>-<名前>` が続いた ID) を参照している箇所を探して示す。参照の規則の SSOT (single source of truth。ある事実を定めている唯一の記述) は、プラグインの規則の文書 [doc-structured-docs.md](../../rules/doc-structured-docs.md) の節「リンク」。

このスキルは文書を書き換えない。

## 手順

1. **前置き**: プロジェクトのルートで、次のコマンドを実行する。出力があれば、その 1 行をそのまま利用者に伝えてから続ける。終了コードが 1 なら、標準エラー出力の文を利用者に伝えて中断する。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/plugin-version-notice"
   ```

2. **ID を決める**: 引数が ID の形 (`d-loans-m-loan` のように、種類の記号と名前をハイフンでつないだもの) なら、それを使う。名前 (「貸出」「モデル「貸出」」「返却期限」など) なら、次の 2 つの両方から、名前が一致する ID を探す。一致するのは、名前そのものか、名前に種類と親を添えた限定付きの名前 (「モデル「貸出」」「節「返却期限」」など) が同じもの。
   - モデル・属性・値・未分類の用語: 用語の索引 `docs/glossary.md` の表の各行の、日本語名のリンクのラベルと ID。
   - 手書きのファイルと節: `docs/domains/` の下の手書きのファイルのアンカー `<a name="<ID>"></a>` と、アンカーの後の空行でない最初の行の見出しの文。アンカーと見出しの間には、空行があることが多い。

   候補が 1 つなら、その ID と実行するコマンドを利用者に示してから、手順 3 に進む。候補が複数なら、候補 (ID と、索引か見出しに書かれた名前) を選択肢にして、どれを探すかを質問する。一致する候補が無ければ、探す ID を質問する。名前を一部に含む ID があれば、それを選択肢に添える。
3. **探す**: プロジェクトのルートで `bin/doc-structured refs <ID>` を実行する。
4. **終了コードが 0 のとき**: 出力をそのまま利用者に伝える。出力の各行は「パス:行:列: <参照している ID> <書いたとおりのリンク> (<行が属する ID>)」で、行が属する ID は、その行を含む最も内側のアンカー付きの節の ID (どの節にも入らない行はファイルの ID)。「(定義の行だけで、本文で使われていない)」の行は、定義の行だけがあって本文で使われていないラベル。「アンカーは無い」の行があれば、その ID の参照先がもう無いこと (名前を変えた後の古いリンクなど) を添えて伝える。
5. **終了コードが 1 のとき**: 標準エラー出力の文を利用者に伝える。「ID … の形が違う」なら、手順 2 に戻って ID を質問し直す。設定ファイルの誤りなら中断する。
6. **終了コードが 2 のとき**: 引数の誤り。出力をそのまま利用者に伝えて中断する。

## このスキルがしないこと

- 見つけた箇所のラベルや本文を、利用者に質問せずに書き換えること。直すときは、利用者が直し方を決めてから直す。
- 候補が複数の名前について、利用者に質問せずに ID を選ぶこと。
- 生成したファイルと記録 (計画と ADR) を探すこと。
