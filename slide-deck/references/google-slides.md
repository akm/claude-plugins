# Google スライドの扱い

スキル `publish` が、Google スライドのコネクタで資料を作り、読み込み、指示を送り、画像で確認するときの方法。入口のサブコマンドの引数・出力・終了コードは書かない。`node <プラグインのディレクトリ>/src/cli.ts <サブコマンド> --help` の出力を参照する (特に `requests --help` が、読み込みで指定する項目と、`build/presentation.json` の期待する形を示す)。

この文書で使う語:

- **コネクタ**: Claude のデスクトップアプリで有効にする、Google ドライブと Google スライドを操作するツールの集まり。
- **資料の ID**: Google スライドの資料の URL の `/d/` の後の部分。サブコマンド `check-outline` が、構成案の URL から取り出して示す。
- **指示のファイル**: サブコマンド `requests` が書く、Google スライドの API のメソッド `presentations.batchUpdate` に渡す指示の配列のファイル (`build/requests-<番号>.json` と `build/requests-notes-<番号>.json`)。

## 使うツール

| コネクタ | ツール | 使う場面 |
| --- | --- | --- |
| Google ドライブ | `create_file` | 新しい空の資料を作る |
| Google スライド | `read_presentation` | 資料を読み込む (項目を指定する) |
| Google スライド | `update_presentation` | 指示のファイルを送る |
| Google スライド | `read_slide_page_thumbnail` | スライドの画像の URL を得る |

ツールの名前は、使う環境で違うことがある。読み込まれていないツールは、ツールの検索 (例: 「google slides」) で読み込む。検索で見つからなければ、使えるツールを一覧にしてから、無いと判断する。Google スライドのコネクタが無ければ、別の方法 (PowerPoint のファイルを Google ドライブにアップロードして変換するなど) を試さずに中断し、有効にするよう利用者に求める。設定されているが無効なら、そのチャットのコネクタの設定で有効にしてもらい、設定されていなければ、追加するコネクタを示す。PowerPoint のファイル (`build/deck.pptx`) を渡すのは、利用者が選んだときだけ。

## 新しい資料を作る

構成案に Google スライドの URL の行が無いときだけ作る。

1. `create_file` を、`title` を構成案の題名、`contentMimeType` を `application/vnd.google-apps.presentation` にして実行する (内容は渡さない)。
2. 結果のファイルの ID から、URL `https://docs.google.com/presentation/d/<ファイルの ID>/edit` を作り、すぐにサブコマンド `write-info` の `--google-slides` で構成案に書き込む。後の手順で失敗しても、作った資料の URL が構成案に残るようにするため。
3. 新しい資料には、タイトルのスライドが 1 枚ある。このスライドは、サブコマンド `requests` が最初の指示のファイルで消す。手で消さない。

## 資料を読み込み、`build/presentation.json` に書く

1. `read_presentation` を、`presentationId` を資料の ID、`fields` を `requests --help` の「読み込みで指定する項目」の文字列 1 つの配列にして実行する。項目を指定しない読み込みは、資料のすべてのレイアウトとマスターを返し、大きくなるので行わない。
2. 結果の JSON を、加工せずに資料のディレクトリの `build/presentation.json` に書く。アプリが結果をファイルに保存したときは、そのファイルをコピーする。結果が会話に返ったときは、項目を足したり、消したり、並べ替えたりせずに、そのまま書く。
3. 期待する形に合わなければ、`requests` が場所と期待する形を示して終了コード 2 になる。読み込みの項目の指定が `requests --help` と同じかを確認してから、読み込みをやり直す。

## 指示のファイルを送る

`requests` は、送る指示のファイルを、送る順に出力に示す。1 つのファイルを送るときは、次のとおりにする。

1. ファイルの内容 (JSON の配列) を Bash の出力として読む (例: `cat <資料のディレクトリ>/build/requests-1.json`)。ファイルは 20,000 字以下に分けてあり、Bash の出力の上限に収まる。
2. `update_presentation` を、`presentationId` を資料の ID、`requests` をファイルの配列そのもの、`writeControl.requiredRevisionId` を送る直前に読み込んだ `build/presentation.json` の `revisionId` にして実行する。指示の中身を変えない。`writeControl` を外さない。
3. 送ると資料の版が変わる。次のファイルを送る前に、資料を読み込み直す。書き込みの応答に含まれる版の ID は使わない。

スキル `publish` は、「資料を読み込んで `build/presentation.json` に書く → `requests` を実行する → 出力の先頭のファイルだけを送る」を、`requests` が「送る指示は無い」と示すまで繰り返す。送るたびに `revisionId` が変わり、作ったスライドの発表者ノートの欄の ID も、作った後に読み込まないと分からないため。作る・作り直すスライドのノートの指示は、スライドを作った後の繰り返しで、ノートの指示のファイルとして出る。

`--recreate-all` を付けたときだけは、`requests` を 1 回だけ実行し、書いたスライドの指示のファイルを、書いた順にすべて送る (どのファイルも、送る直前に資料を読み込み、その `revisionId` を付ける。このときの読み込みは、項目 `revisionId` だけでよい)。理由は `requests --help` の `--recreate-all` の説明にある。送り終えたら、`--recreate-all` を付けずに上の繰り返しを行い、ノートを入れる。

### 送ったときの誤り

- **`The required revision ID ... does not match the latest revision.`**: 読み込んだ後に、資料が変わった (利用者が編集したなど)。何も適用されていない。資料を読み込み直し、`requests` からやり直す。
- **ほかの誤り**: 1 回の送信の指示は、1 つでも誤りがあれば、どれも適用されない。指示のファイルを手で直して送らずに、誤りの文と、送ったファイルのパスを利用者に示して中断する。ツールの不具合の可能性があるため。

途中で中断しても、もう一度 `publish` を実行すれば、資料のスライドの ID から残りの作業が決まり、残りだけを行う。ただし、`--recreate-all` の途中で中断したときは、構成案の slide-deck の版の行をまだ書き込んでいないので、もう一度すべてを作り直すかを質問することになる。

## ID の形

- **スライドの ID**: `sd_<キー>_<ハッシュ値>`。ハッシュ値は、題名・一言・図の要素とテーマのフォントから求めた 16 進数 10 文字で、位置と発表者ノートを含めない。題名・一言・図のどれかを変えるとハッシュ値が変わり、スライドを作り直す。ノートだけを変えたときは、作り直さずにノートだけを入れ直す。
- **図形の ID**: `<スライドの ID>_<番号>` (番号は 3 桁まで)。
- **キーの無いスライド**: ID が `sd_<キー>_<ハッシュ値>` の形でないスライド (利用者が Google スライドで足したもの)。`requests` は内容を変えず、直前のキーのあるスライドと一緒に動かす。
- **手で直した内容**: キーのあるスライドを利用者が Google スライドで直しても、ID は変わらない。そのスライドを作り直すと、手で直した内容は失われる。消すときも同じ。

## 画像で確認する

1. スライドごとに、`read_slide_page_thumbnail` を、`presentationId` を資料の ID、`pageId` をスライドの ID、`thumbnailProperties.thumbnailSize` を `MEDIUM` (幅 800 ピクセル) にして実行し、画像の URL (`contentUrl`) を得る。スライドの ID は、最後に書いた `build/presentation.json` の配列 `slides` にある。
2. 画像の URL を 6 枚ずつ、画像をまとめるツール `python/slide_deck_tools/thumbs_grid.py` に、キャッシュの venv の Python で渡す。venv のパスは、サブコマンド `setup status` の出力の「venv」の行にある。

   ```bash
   <venv のパス>/bin/python <プラグインのディレクトリ>/python/slide_deck_tools/thumbs_grid.py <資料のディレクトリ>/build/thumbs-1.png <URL> <URL> ...
   ```

   引数・出力・終了コードは、`thumbs_grid.py --help` の出力を参照する。終了コード 2 (取得できない URL など) なら、誤りの文を利用者に示し、画像での確認をしていないことを伝える。
3. 書いた画像を読み、最後の 1 文字だけの行・はみ出し・位置のずれ・重なりを探す。

## Google スライドの API への対処

PowerPoint のファイルと同じ見た目にするために、指示の作成で行っている対処。どれも理由をファイル [src/gslides/requests.ts](../src/gslides/requests.ts) のコメントに書いてある。画像で見つけた違いが、ここにある対処の結果かを判断するのに使う。

| 対処 | 理由 |
| --- | --- |
| 図形の大きさを、基準の大きさ (3,000,000 EMU) と拡大率で表す | Google スライドは、読み込むと大きさを常にこの形で返す。後から大きさを変えるときに、読み込んだ拡大率をそのまま計算に使えるようにするため |
| 大きさが 0 の軸 (縦や横の線の幅か高さ) は、大きさ 0・拡大率 1 にする | 拡大率 0 を受け付けるかを確認していないため |
| 円・円柱・山形・五角形の矢印の中の文字は、図形に重ねた文字の箱にする | Google スライドは、これらの図形の中の文字を、図形の内側の狭い範囲に収めて折り返すため。重ねる文字の箱は、図形の外形に合わせる |
| 文字の箱は、データの余白の分だけ狭めてから、Google スライドの余白 (左右 0.1 インチ・上下 0.05 インチ) の分だけ広げる | Google スライドの余白は API で変えられないため。文字を配置する範囲がデータと一致する |
| 幅と高さのどちらも 1 インチより大きい角の丸い四角は、四角で描く | 丸みの大きさは API で変えられず、大きな箱では丸みが大きくなりすぎるため |
| 箇条書きの字下げを 16 ポイントにする | デフォルト値は大きく、幅の狭い箱では行が折り返されるため。はみ出しの見積もりと PowerPoint の書き出しも同じ値を使う |
| 書式の範囲に、段落の末尾の改行の文字を含める | 含めないと、改行の文字だけがデフォルトの大きさのまま残り、その行が高くなるため |
| 右から左・下から上への線は、拡大率を負にして描く | 線の向きは、始点と終点ではなく拡大率の正負で表すため |
| 線は `createLine` の `category` で作る | `lineCategory` は非推奨のため |
| マスターの配色を `updatePageProperties` の `colorScheme` で、テーマの 12 色に変える | 図形の色をテーマの色で指定しているので、配色を変えればすべてのスライドの色が変わるため。読み込んだ配色が同じなら変えない |
| スライドはレイアウト `BLANK` で作り、題名は普通の文字の箱にする | 元にしたツールと同じ作り方で、本物の Google スライドで動くことを確認した使い方の範囲に収まるため。題名の箱の位置と書式は、PowerPoint の題名の箱と同じ |

## できないこと

- **スライド番号**: API では付けない (レイアウト `BLANK` のスライドに、スライド番号のプレースホルダーを作れないため)。利用者に、メニューの「挿入 > スライド番号」で付けてもらう。
- **表・画像・グラフ**: スライドのデータが持たないので、作らない。
- **開いている資料への反映**: 利用者が開いている資料に、送った変更がすぐ表示されないことがある。表示されなければ、資料を再読み込みしてもらう。
