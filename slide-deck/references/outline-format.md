# 構成案の書式

構成案 (資料のディレクトリのファイル `outline.md`) の書式の SSOT (single source of truth。ある事実を定めている唯一の記述)。スキル `outline` が書き、スキル `build` と `publish` が読む。題名・一言・発表者ノートは、資料ごとのスクリプト `deck.ts` には書かず、構成案にだけ書く。

この文書で使う語:

- **資料のディレクトリ**: 利用者のプロジェクトの中で、1 つの資料の `outline.md` と `deck.ts` を作るディレクトリ。スキル `outline` が毎回利用者に質問して決める。
- **キー**: スライドを指す名前。構成案で決め、並べ替えても変えない。Google スライドのスライドの ID に入る (ファイル [google-slides.md](google-slides.md) の節「ID の形」)。
- **一言**: そのスライドで伝えたいことの 1 文。スライドの下に表示する。

## 例

ファイル [examples/sample/outline.md](../examples/sample/outline.md) (見本の資料「キャッシュのしくみ」) の先頭:

```markdown
# キャッシュのしくみ

- 読者: キャッシュを使ったことが少ない開発者
- ねらい: キャッシュが速くなる理由と、古い値が残る問題と、その対処を理解してもらう
- 形: 図を中心にし、1 枚の文は 1〜2 文まで
- 固有名: 一般化する

## 1. 読み出し

### read-path: 読み出しの流れ
- 図: アプリケーション・キャッシュ・DB (円柱) の 3 つの箱を左から並べ、番号の付いた矢印で読み出しの順序を示す
  - ① アプリケーションがキャッシュに値を問い合わせる
  - ② 値が無ければ、キャッシュが DB から読む
  - ③ 読んだ値をキャッシュに残す
  - ④ 値をアプリケーションに返す
- 一言: 2 回目からは、DB まで読みに行かずに済む

アプリケーションは、まずキャッシュに値を問い合わせます。
キャッシュに値が無いときだけ、DB から読みます。

DB から読んだ値はキャッシュに残すので、同じ値を続けて読むときは DB に問い合わせません。
```

## 資料の題名と資料の情報

1 行目 (前には空行だけを書ける) に `# <資料の題名>` を書き、その後に、資料の情報を `- <項目>: <値>` の行で書く。項目の行の間には、空行だけを書ける。

| 項目 | 省略 | 値 | 書くもの |
| --- | --- | --- | --- |
| 読者 | できない | 資料を読む人 | スキル `outline` |
| ねらい | できない | 読者に何を理解してもらうか | スキル `outline` |
| 形 | できない | 1 枚の文の量・図と文の割合など | スキル `outline` |
| 固有名 | できる | `一般化する` か `そのまま書く`。実測の値などの事例を、プロジェクトの名前と一緒に書くかの、利用者の回答 | スキル `outline` (利用者に質問した後) |
| Google スライド | できる | `https://docs.google.com/presentation/d/<資料の ID>` で始まる URL | スキル `publish` (サブコマンド `write-info`) |
| slide-deck の版 | できる | `数.数.数` の形の、最後に publish したプラグインの版 | スキル `publish` (サブコマンド `write-info`) |

- 表に無い項目・同じ項目の 2 回目・空の値は、誤りになる。
- 固有名の行が無いうちは、スキル `outline` が利用者に質問する。行があれば、次からは質問しない。
- Google スライドと slide-deck の版の行は、手で書かない。スキル `publish` が、サブコマンド `write-info` で書き込む。書き込む行のほかは変わらない。

## 章とスライド

- 章は `## <章の名前>` で書く。章は省略できる。章を書くなら、スライドを 1 枚以上入れる。章の名前はスライドには出ない。
- スライドは `### <キー>: <題名>` で書く。スライドの順序は、構成案の見出しの順序で決まる。
- キーは、英小文字・数字・ハイフン (`[a-z0-9-]`) の 1〜32 文字にし、資料の中で 1 つにする。題名を変えても、キーは変えない (キーを変えると、Google スライドでは別のスライドとして作り直す)。
- 利用者の依頼に無く、採否を利用者に質問するスライドは、`### 【提案】<キー>: <題名>` で書く。採用したら【提案】を外し、採用しなかったらスライドの見出しから次の見出しの前までを消す。【提案】が残っていると、スキル `build` のサブコマンド `check` が指摘にする。
- `####` 以下の見出しは書けない。

## スライドの中身

スライドの見出しの直後に、次の 2 行を 1 回ずつ書く。ほかの項目 (補足・注など) は書けない。

- `- 図: <図の説明>`: スキル `build` が `deck.ts` に図を書くときの説明。`- 図:` の行の後の、字下げした行も図の説明に含める。複数の図や、図の中の順序は、字下げした行で書く。図の説明はスライドには出ない。
- `- 一言: <1 文>`: スライドの下に表示する文。1 行で書く。

2 行の後に空行を 1 行以上空けて、発表者ノートの段落を書く。

- ノートは省略できる。
- 段落の中の改行は残り、段落の間は空行 1 つになる。
- ノートは地の文だけにする。`- ` で始まる行と、字下げした行は書けない。

## どこにも書けないもの

- 区切りの線 `---`
- 題名の行の前と、資料の情報の行の間の、空行以外の行

## 書式の検査

サブコマンド `check-outline` が、構成案の書式だけを検査し、誤りを行番号付きですべて示す (`deck.ts` とライブラリは要らない)。スキル `build` のサブコマンド `check` も、最初に同じ検査をする。引数・出力・終了コードは、`node <プラグインのディレクトリ>/src/cli.ts check-outline --help` の出力を参照する。
