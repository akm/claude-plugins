# slide-deck:outline: 構成案を作る・直す

説明資料の構成案 (資料のディレクトリのファイル `outline.md`) を作る、または直す。構成案は、スライドの順序・題名・一言・図の説明・発表者ノートの SSOT (single source of truth。ある事実を定めている唯一の記述) で、後のスキル `build` と `publish` は構成案から読む。資料を直す依頼も、まずこのスキルで構成案を直してから、スライドを直す。

構成案の書式は、ファイル [references/outline-format.md](../../references/outline-format.md) を読んでから書く。入口のサブコマンドの引数・出力・終了コードは、`node "${CLAUDE_PLUGIN_ROOT}/src/cli.ts" <サブコマンド> --help` の出力を参照する。

この文書で使う語:

- **資料のディレクトリ**: 1 つの資料の `outline.md` と `deck.ts` を作る、利用者のプロジェクトの中のディレクトリ。
- **キー**・**一言**・**【提案】**: ファイル [references/outline-format.md](../../references/outline-format.md) の説明のとおり。

## 手順

例は、プラグインに同梱した見本の資料 (ファイル [examples/sample/outline.md](../../examples/sample/outline.md)。題材は「キャッシュのしくみ」) を作る場合で示す。

1. **資料のディレクトリを質問する**: 新しく作るときも、直すときも、毎回質問する。git で管理するかはプロジェクトごとに違うので、このスキルは決めない。案として `tmp/slides/<資料名>/` を添える (例: `tmp/slides/cache/`)。直すときは、この会話で使ったディレクトリも案に添える。直すときは、そのディレクトリに `outline.md` があることを確認する。
2. **資料の情報を決める**: 新しく作るときは、依頼から読者・ねらい・形を読み取る。依頼に無いものは、利用者に質問する。
   - 例: 読者「キャッシュを使ったことが少ない開発者」、ねらい「キャッシュが速くなる理由と、古い値が残る問題と、その対処を理解してもらう」、形「図を中心にし、1 枚の文は 1〜2 文まで」。
3. **参考にした資料を探す**: 依頼で検索する語が指定されていれば、その語でウェブを検索する。参考にした資料 (題名と URL) を、最後のスライドに載せる。載せる前に、一覧を利用者に示して承認を得る。依頼で語が指定されていなければ、検索しない。
4. **構成案を書く**: 書式のとおりに `outline.md` を書く。
   - スライドごとに、キー・題名・図の説明 (`- 図:`)・一言 (`- 一言:`)・発表者ノートを書く。図の説明は、スキル `build` が図を描けるよう、要素・並べ方・矢印の向き・色の意味を具体的に書く。描ける要素は、ファイル [references/deck-script.md](../../references/deck-script.md) の節「部品の関数」の範囲 (表・画像・グラフは描けない)。
   - 依頼に無いスライドを足すときは、見出しを `### 【提案】<キー>: <題名>` にする。
   - 事例 (実測の値・障害の経緯など、特定のプロジェクトで起きたこと) を書くとき、資料の情報に固有名の行が無ければ、プロジェクトの名前と一緒に書くか、一般化して書くかを利用者に質問し、回答を固有名の行 (`一般化する` か `そのまま書く`) に書く。行があれば、質問せずにその値に従う。
   - 直すときは、依頼された箇所だけを直す。キーは変えない (キーを変えると、Google スライドでは別のスライドとして作り直す)。Google スライドの URL と slide-deck の版の行は、手で書かない (スキル `publish` が書く)。
5. **文章の規約を当てる**: 題名・一言・発表者ノートと、図の説明に書いたスライドの文に、利用者とプロジェクトの文章の規約 (使わない表現・語彙の選び方。利用者とプロジェクトの `CLAUDE.md` など) を当てる。プロジェクトに wording-guard の設定 (ファイル `.claude/akm-claude-plugins/wording-guard/config.json`) があれば、スキル `wording-guard:wording-guard` で `outline.md` を検査し、指摘を直す。
6. **書式を検査する**: 資料のディレクトリを渡して、サブコマンド `check-outline` を実行する。`deck.ts` とライブラリは要らない。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/src/cli.ts" check-outline tmp/slides/cache
   ```

   - **終了コード 0**: 書式の誤りは無い。見本の資料の出力は次のとおり。

     ```text
     構成案の書式の誤りは無い (スライド 4 枚)
     Google スライド: 無い
     slide-deck の版: 無い (今の版: 0.1.0)
     固有名: 一般化する
     ```

   - **終了コード 1**: 書式の誤りを行番号付きで示す。書式のとおりに直し、もう一度実行する。ただし、Google スライドの行か slide-deck の版の行の値の誤りは、直す前に、ファイル [references/outline-format.md](../../references/outline-format.md) の節「資料の題名と資料の情報」のとおりに利用者に質問する。
   - **終了コード 2**: 出力 (標準エラー出力) をそのまま利用者に伝えて中断する。
7. **【提案】の採否を質問する**: 出力に「【提案】が付いたスライド」があれば、一覧をまとめて示し、スライドごとに採否を利用者に質問する。採用したものは見出しから【提案】を外し、採用しなかったものは、その見出しから次の見出しの前までを消す。直したら手順 6 に戻る。
8. **報告する**: `outline.md` のパスとスライドの枚数を伝える。続けて PowerPoint のファイルを作るならスキル `slide-deck:build`、Google スライドに反映するなら、`build` の後にスキル `slide-deck:publish` を使うことを伝える。

## このスキルがしないこと

- 資料のディレクトリ・読者・ねらい・形・固有名の扱い・【提案】の採否を、利用者に質問せずに決めること。
- 依頼で指定されていない語でウェブを検索すること。参考にした資料の一覧を、利用者に示さずに載せること。
- 資料ごとのスクリプト `deck.ts` を書くこと、PowerPoint のファイルを作ること。スキル `build` が行う。
- Google スライドを変えること、構成案に Google スライドの URL と slide-deck の版の行を書くこと。スキル `publish` が行う。
