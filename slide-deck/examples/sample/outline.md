# キャッシュのしくみ

- 読者: キャッシュを使ったことが少ない開発者
- ねらい: キャッシュが速くなる理由と、古い値が残る問題と、その対処を理解してもらう
- 形: 図を中心にし、1 枚の文は 1〜2 文まで
- 固有名: 一般化する

## 1. 読み出し

### read-path: 読み出しの流れ
- 図: アプリケーション・キャッシュ・DB (円柱) の 3 つの箱を左から並べ、番号の付いた矢印で読み出しの順序を示す
  - ① アプリケーションがキャッシュに値を問い合わせる
  - ② 値が無ければ、キャッシュが DB から読む
  - ③ 読んだ値をキャッシュに残す
  - ④ 値をアプリケーションに返す
- 一言: 2 回目からは、DB まで読みに行かずに済む

アプリケーションは、まずキャッシュに値を問い合わせます。
キャッシュに値が無いときだけ、DB から読みます。

DB から読んだ値はキャッシュに残すので、同じ値を続けて読むときは DB に問い合わせません。

### hit-miss: ヒットとミス
- 図: 2 枚のカードを左右に並べる。左はヒット (キャッシュに値がある)、右はミス (キャッシュに値が無い) で、それぞれ起きることを箇条書きにする
- 一言: ヒットの割合が高いほど、DB の負荷が下がる

ヒットの割合は、同じ値を何度読むかで決まります。

## 2. 古い値

### stale: 古い値が残る
- 図: 山形の図形で、DB の値を更新する → キャッシュは古い値のまま → 古い値を返す、の順序を示す。下に、古い値が残る期間を破線の枠で示す
- 一言: DB を更新しても、キャッシュの値は自動では変わらない

### expire: 期限と消し方
- 図: 2 つの対処を左右に並べる。左は有効期限 (決めた時間が過ぎたら消す)、右は更新するときに消す。間に両向きの矢印を置き、組み合わせられることを示す
- 一言: 期限と消し方を組み合わせて、古い値が残る時間を短くする

有効期限だけでは、期限が切れるまで古い値が残ります。
更新するときに消す方法だけでは、消し忘れた値が残り続けます。
