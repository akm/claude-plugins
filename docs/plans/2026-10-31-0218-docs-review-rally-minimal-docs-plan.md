# review-rally の文書を、実現することと手順だけに減らす - Plan

## 問題

スキル `review-rally` の文書 (ファイル `review-triage/skills/review-rally/SKILL.md` と、ディレクトリ `review-triage/skills/review-rally/references/` の 4 ファイル。計 476 行) は、手順と様式に加えて、理由・経緯・確認した日付・検出しないものの説明を多く含む。

- 説明が手順を言い直しているので、手順を変えるたびに、説明と手順が矛盾する。ブランチ `feat/review-request-target-dir-151` のレビューの 3〜8 回目は、この矛盾への指摘が続いた。
- スキルが何を実現するかが書かれていないので、ある手順や説明が必要かどうかを判断する基準が無い。

## 方針

1. SKILL.md に、実現することを 1 行ずつ書く。
   1. レビューの結果を、Skill ツールで `review-triage` を呼び出してトリアージする。
   2. 採択が 0 件なら、収束として終了する。
   3. 採択したものを、`review-triage-fix` で直す。
   4. 直したものを、レビューのセッションに再び依頼する。
   5. 収束しなくても停止する。
   6. どの回も、同じ条件でレビューさせる。
2. 文書に残すのは、手順・様式・停止の決定表と、次の基準に当たる理由だけにする。理由は 1 文で書く。
   - 基準: その手順を変えたり消したりしてもエラーにならず、実現することが損なわれても利用者が知る手段が無い。
   - 例: アプリが起動元より上のモデルを無視すること (起動の直後に値を確認する理由)。レビュアのテストがメインの `.git` を書き換えうること (ブランチの一覧を比べる理由)。
3. 次のものは消す。これは例であって、消すものの範囲ではない。
   - 経緯 (「#151 の試しで」「2026-10-29 に確認した」など)。経緯は Issue #151 と、ファイル `docs/plans/2026-10-29-0852-feat-review-rally-plan.md` に残っている。
   - 手順を言い直す説明 (SKILL.md の「前提知識」「原則」のうち手順と重なるもの、「このスキルが検出しないもの」)。
   - 変えればエラーになるので、利用者が知ることのできる理由 (フォアグラウンドの `sleep` が拒否されること、など)。
   - スキル `review-loop` との比較。
4. 条件・タスク・前提と制約は、文書の層として書かない。ファイルも増やさない。

## 実装単位

どの単位も、方針の 2・3 を当てはめて修正する。単位ごとにコミットする。

- U1: SKILL.md。実現することを書き、「前提知識」「原則」「このスキルが検出しないもの」を消す。手順に無い内容は、手順か報告に移すか、消す。レビューの 8 回目の P1 (SKILL.md の 68 行目) は、この単位で対象の節が無くなる。
- U2: `references/round.md`
- U3: `references/session.md` と `references/arguments.md`
- U4: `references/stops.md`
- U5: 確認。残った文が、手順・様式・決定表か、基準に当たる理由のどれかであることを、文ごとに確認する。doc-dag で参照が切れていないこと、wording-guard を通すこと、review-rally で全量をレビューする。

## 計画の後に決めたこと

- 作業するブランチ。このブランチ `feat/review-request-target-dir-151` で行い、#151 の PR に含める (2026-10-31 に利用者が決めた)。
