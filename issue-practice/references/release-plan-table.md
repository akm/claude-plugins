# リリース計画 Issue の順番の表

リリース計画 Issue (用語は [terms.md](terms.md)) の本文には、リリースの順番を表で書きます。この文書は、表の場所・列・リリース Issue の参照の書き方と、表から「今のリリース」と「次のリリース」を決める規則 (計画の R36) を決めます。リリース計画 Issue の本文のほかの部分と題名は、スキル `release-plan` の文書が決めます。

この文書と、モジュール `issue-practice/scripts/issue_practice/releaseplan.py` が、表の書式の [SSOT](../../CONCEPTS.md#ssot) です。検査のスクリプトのサブコマンド `release current` が、この規則で「今」と「次」を返します。スキルは、表を読んで自分で「今」と「次」を決めません。

## 表の場所

本文の見出し `## リリースの順番` の節 (次のレベル 2 以上の見出しの手前まで) に、表を 1 つだけ書きます。コードブロックの中に書いた見出しと表は数えません。

## 表の形

```markdown
## リリースの順番

| 順 | リリース Issue | 主題 |
| --- | --- | --- |
| 1 | #12 | バックアップ一式 |
| 2 | #15 | 一覧の絞り込み |
```

- 見出しの行は、`| 順 | リリース Issue | 主題 |` の 3 列そのものにします。列を足したり、順序を変えたりしません。
- 列「順」は、1 から始まる連番です。上の行ほど先にリリースします。
- 列「リリース Issue」は、リリース Issue の参照を `#<番号>` の形で 1 つだけ書きます。リリース Issue は、リリース計画 Issue と同じリポジトリにあります。同じリリース Issue を 2 つの行に書きません。
- 列「主題」は、リリースマイルストーンの名前の主題 (`R<番号> (主題)` の括弧の中。計画の R41) を書きます。人が表を読むときのためのもので、検査のスクリプトは空でないことだけを確認します。

形が違う表 (見出しの行が違う・連番になっていない・参照が `#<番号>` でない・同じリリース Issue が 2 回ある) は、誤りとして扱います。スキルは中断し、見つけたことを示して利用者に質問します (計画の R8)。

## 有効なリリース計画 Issue

「今」と「次」は、ラベル `current` の付いた開いているリリース計画 Issue の表から決めます。

| ラベル `current` の付いた計画の数 | 扱い |
| --- | --- |
| 0 | まだ計画が無い。「今」も「次」も無い |
| 1 | その計画の表を読む |
| 2 | ラベル `current` の付け替えの途中 (計画の R38)。後に作られたほう (`createdAt` が新しいほう) の表を読む |
| 3 以上 | 決めた形が崩れている。誤りとして扱う |

リリース対象が複数あるとき (リポジトリにラベル `release-target:<名前>` があるとき) は、リリース対象を指定し、そのラベルの付いた計画だけを数えます。リリース対象を指定しないと、リリース対象の一覧を返して、誤りとして扱います。スキルは、どのリリース対象かを利用者に質問します (計画の R36)。

## 「今」と「次」

表を上の行から順に見て、次の規則で決めます (計画の R36)。

- **今のリリース**: 閉じていないリリース Issue のうち、題名に `[DRAFT]` が無い最初のもの。
- **次のリリース**: 表で「今」より下にある、閉じていない最初のリリース Issue。題名に `[DRAFT]` があってもかまいません。
- 「今」が無いときは、表で閉じていない最初のリリース Issue を「次」にします。
- 「次」が無いときは、スキルは、未定にするか、スキル `release-plan` で次のリリースを作るかを利用者に質問します。

例 (表の 1 行目が閉じていて、2 行目の題名に `[DRAFT]` があるとき): 「今」は無く、「次」は 2 行目のリリース Issue です。

「今」と「次」に決めたリリース Issue について、次のことも確認します。どれかが合わなければ、誤りとして扱います (計画の R8)。

- リリース Issue が、PR ではなく Issue である。
- リリースマイルストーン (名前が `R<リリース Issue の番号> (主題)`。リリース対象があれば `R<番号> <リリース対象> (主題)`) が 1 つだけあり、開いている。
- マイルストーンの説明にリリース Issue の URL があり、リリース Issue の本文にマイルストーンの URL がある (お互いの URL)。
- 「今」に決めたリリース Issue に、記録のコメント `draft-removed` がある (題名の `[DRAFT]` を外したときに書く記録。形は [record-comments.md](record-comments.md))。

## 実行中のリリース

記録のコメント `release-start` があるリリース Issue は、実行中です (計画の R46)。後で行う作業を切り出すときは、実行中の「今」のリリースを、入れるリリースとして選べません (計画の R13)。サブコマンド `release current` に `--carve-out` を付けると、実行中の「今」を選べないものとして返します。
