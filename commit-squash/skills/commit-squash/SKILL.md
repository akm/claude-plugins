# commit-squash: 未 push のコミットをまとめて減らす

作業中は「直しては見つかり、また直す」で履歴が膨らむ。**同じファイルの同じ箇所を何度も往復した記録は、レビュアには読む価値がない。** 到達点だけを見せる形にまとめ直す。

まとめるのは**未 push のコミットだけ**。push 済みのコミットは決して書き換えない。これはこのスキルが前提とする唯一の絶対条件で、[references/history-rewriting.md](references/history-rewriting.md) が理由と適用範囲を定める。

## 前提の確認

始める前に必ず確認する。1 つでも満たさなければ、そこで止めて人間に報告する。

1. **作業ツリーがクリーン** (`git status --porcelain` が空)。未コミットの変更があるとまとめる対象が曖昧になる。
2. **起点より後のコミットがすべて未 push** であること。

   ```bash
   git log --format=%h <起点>..HEAD | while read c; do
     git branch -r --contains $c 2>/dev/null | grep -q . && echo "push 済み: $c"
   done
   ```

   何も出なければよい。起点自体がリモートに含まれているのは問題ない (そこは書き換えないため)。**1 行でも出たら、そこで止めて人間に報告する。**
3. **最終ツリーの記録**。まとめても中身が変わっていないことを最後に検証するため、先に控える。

   ```bash
   git rev-parse HEAD^{tree}
   ```
4. **バックアップブランチを作る**。

   ```bash
   git branch backup/before-squash-$(git rev-parse --short HEAD) HEAD
   ```

## 手順

1. **現状を把握する。** 各コミットが触ったファイルを一覧にする。

   ```bash
   for c in $(git log --format=%h --reverse <起点>..HEAD); do
     echo "$c $(git log -1 --format=%s $c)"
     git show --stat --format='' $c | grep '|' | sed 's/^/    /'
   done
   ```

2. **グループに分ける。** [references/grouping-rules.md](references/grouping-rules.md) の判断基準に従う。**基準で決まるものは自分で決め、決まらないものだけ人間に確認する。**

3. **往復した箇所を見つける。** 途中で入れて後で外した変更は、まとめると消える。**消えてよいかを確認するため、必ず把握しておく。**

   ```bash
   # 例: draft という語の出現数が途中で増えて最後に減っていないか
   for c in $(git log --format=%h --reverse <起点>..HEAD -- <ファイル>); do
     printf '  %s 出現=%s\n' "$c" "$(git show $c:<ファイル> | grep -c '<語>')"
   done
   ```

   往復は「まとめてよい」強い根拠になる (正味の差分が小さい)。一方で、**往復の経緯そのものが知見のこともある** — その場合はメッセージ本文に残す (手順 5)。

4. **積み直す。** rebase は使わない ([references/why-not-rebase.md](references/why-not-rebase.md))。起点に新しいブランチを作り、最終形からファイル単位で取り出して積む。

   ```bash
   git checkout -b squash/<識別子> <起点>
   # グループごとに:
   git checkout <最終コミット> -- <そのグループのファイル群>
   git status --porcelain          # 意図したファイルだけか確認する
   git commit --trailer 'Rules-Checked: yes' -F - <<'EOF'
   <メッセージ>
   EOF
   ```

   **順序は依存の向きに従う。** 定義を足すコミットは、それを参照するコミットより先に置く。ファイルの移動 (`git mv`) を含むグループは、その移動を最初に行ってから中身を上書きする。

   **1 グループが複数の中間状態を経ている場合**は、その途中のコミットから取り出す。例: lint 対応を分離するなら、lint 直前のコミットから取り出して 1 つ目を作り、次に lint のコミットから取り出し、最後に最終形から取り出す。

5. **メッセージを書く。** 件名は**到達点**を述べる (「〜を直す途中で気づいて〜も直した」ではなく「〜する」)。本文には次を書く。

   - 何を実現したか
   - **なぜその形なのか** — 特に、素通りしていた経路・回避された経路・実際に起きた事故。これは将来同じ穴を作らないための知識で、まとめても失ってはいけない
   - 途中で方針を変えたなら、**変えた理由**。「当初こう書いたが、これこれが見つかったので今の形にした」

   中間の試行錯誤そのもの (何度直したか) は書かない。

6. **各コミットが単体で壊れていないか確かめる。**

   ```bash
   for c in $(git log --format=%h --reverse <起点>..HEAD); do
     git checkout -q $c
     go build ./... 2>/dev/null && go vet ./... 2>/dev/null \
       && echo "  OK   $c" || echo "  NG   $c"
   done
   git checkout -q squash/<識別子>
   ```

   NG が出たらグループ分けが間違っている (依存の向きか、分割すべきでないものを分割した)。手順 2 に戻る。

7. **最終ツリーの一致を検証する。** **これが最も重要な検証**。まとめる前後で中身が 1 バイトも変わっていないことを示す。

   ```bash
   git rev-parse HEAD^{tree}                    # 手順 0-3 で控えた値と一致するか
   git diff backup/before-squash-<sha> HEAD --stat   # 何も出なければ一致
   ```

   一致しなければ**必ず原因を突き止める**。取りこぼしたファイルがあるか、余計なものを含めたかのどちらか。

8. **ゲートを通す。** そのリポジトリの検査 (lint・テスト・ビルド・ドキュメント検査など) を実行する。**まとめる前に通っていたものが、まとめた後も通ることを確かめる** — 積み直しで取りこぼしがあれば、ここで落ちる。

9. **ブランチを付け替える。**

   ```bash
   git checkout <元のブランチ>
   git reset --keep squash/<識別子>
   ```

   **`--hard` ではなく `--keep` を使う。** `--hard` は未コミットの作業ごと消すため、ここでは使わない ([references/history-rewriting.md](references/history-rewriting.md))。付け替え後、push 済みの先端が書き換わっていないことを再確認する。

   ```bash
   git rev-parse origin/<ブランチ>   # これが新しい履歴に含まれるか
   git merge-base --is-ancestor origin/<ブランチ> HEAD && echo "push 済み履歴は無傷"
   ```

10. **後片付けを報告する。** バックアップブランチと作業ブランチが残る。**自分では削除せず、人間に依頼する。** バックアップは、まとめ方に問題が見つかったときの唯一の戻り先で、消してよいかを判断できるのは結果を確認した人間だけ。

## 原則

- **push しない。** まとめた履歴を push するかは人間が決める。
- **中身を変えない。** まとめる作業で「ついでに直す」ことはしない。改善点に気づいたら、まとめ終わってから別のコミットにする。
- **迷ったら分けない側に倒す。** コミットを 1 つ減らす利益より、無関係な動機が混ざる害のほうが大きい。
