# 履歴を書き換える操作の境界

このスキルは履歴を書き換える。**書き換えてよい範囲を間違えると、他人の作業を壊す。** 境界を定める。

## 判定の軸は「push 済みか」だけ

**push 済みのコミットは決して書き換えない。** それ以外の軸 (古い / 新しい、自分が書いた / 書いていない) は判定に使わない。

push 済みのコミットは、他人がすでに取得しているかもしれない。書き換えると、取得済みの履歴と食い違い、相手の手元で解決不能な分岐が起きる。**自分の手元では成功したように見えるのが、この事故の質の悪いところ。**

起点自体が push 済みであるのは問題ない。**起点は書き換えず、その後ろに積み直すため。**

## このスキルが使う操作と、その安全性

| 操作 | 使う場面 | 安全である理由 |
| --- | --- | --- |
| `git checkout -b` (起点から) | 積み直しの土台 | 既存の履歴に触れない |
| `git checkout <最終> -- <ファイル>` | 最終形からの取り出し | 作業ツリーだけを変える |
| `git reset --keep` | ブランチの付け替え | 未コミットの変更があれば中断する。消さない |

## 使わない操作

- **`git reset --hard`** — 未コミットの作業ごと消す。push 状態に関わらず使わない。ブランチの付け替えは `--keep` で足りる。**`--keep` は消す前に中断してくれるが、`--hard` は黙って消す。** この違いだけが理由で十分。
- **`git push --force` / `--force-with-lease` / `-f`** — push 済み履歴を外へ書き換える。このスキルは push しないので、そもそも到達しない。
- **`git filter-branch` / `git filter-repo`** — 履歴の全書き換え。範囲が「未 push だけ」に収まらない。
- **`git rebase -i`** — 使わない理由は [why-not-rebase.md](why-not-rebase.md) が別に述べる (安全性ではなく、衝突と検証可能性の問題)。

## 止まるべきとき

次のいずれかに当たったら、**回避策を探さずその場で止めて人間に報告する。**

- 起点より後に push 済みのコミットが 1 つでもある
- 作業ツリーがクリーンでない
- 最終ツリーのハッシュが一致しない (手順 7)
- ブランチの削除が必要になった

**これらは「工夫すれば通せる」種類の障害ではない。** 通そうとすると、このスキルが守っている性質そのものが壊れる。

## リポジトリ側の防御との関係

lappds では、上記の禁止操作が `.claude/settings.json` の `deny` と PreToolUse フックで機械的にも止まる。**その防御が無いリポジトリでも、この文書の規則は同じように守る。** 機械的に止まらないことは、やってよいことを意味しない。
