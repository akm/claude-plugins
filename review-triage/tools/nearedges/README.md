# nearedges

Markdown の修正の差分から、**近くの辺** — 変更した箇所と同じ表の全行・同じ箇条書きとその親・同じ節の全文・変更行が参照する先 — を列挙する。`review-triage-fix` の段 3 (修正) でコミットの前に読み直す範囲を、人の判断ではなく差分から決めるための道具 ([verification.md](../../skills/review-triage-fix/references/verification.md) の観点 B)。

**なぜ要るか。** 修正の波及先のうち、別のファイル・別の節にあって同じ語を共有するもの (遠くの辺) は grep で辿れる。同じ表の他の行・同じ行の他の列・同じ段落の次の文は同じ語を共有しないので目で読むしかなく (近くの辺)、読む範囲を人が決めると省かれる。省かれた回は次のレビューの採択として現れる ([#56](https://github.com/akm/claude-plugins/issues/56))。

## 何を列挙するか

| 変更行の種類 | 列挙する範囲 |
| --- | --- |
| 表のセル | その表の全行 (見出し行を含む) |
| 箇条書きの項目 (字下げした続きの行を含む) | 同じ箇条書き全体と、その親 (直前の段落か見出し) |
| 段落の文・コードフェンスの中 | 同じ節 (直前の見出しから、同じ深さ以上の次の見出しの前まで) の全文 |
| 変更行の中のリンク (`[…](#アンカー)`・`[…](別のファイル.md#アンカー)`) | 参照先の節 (アンカーが無ければファイル全体)。`http(s)://` は対象外 |

削除だけの変更は、削除の直後の位置を変更行として扱う。同じ範囲は 1 つにまとめ、その範囲を読む理由になった変更行を添える。

**`-hints` を付けると、差分の種類に応じて当てる検証の観点も提示する** (観点の定義の正本は [verification.md](../../skills/review-triage-fix/references/verification.md))。

| 差分に現れるもの | 提示する観点 |
| --- | --- |
| 表・箇条書き・段落・リンク | B (並びを読み直す) — 上の表の範囲 |
| 数 (「3 つ」「2 件」など) | C (数える単位と範囲を数字より先に決める) |
| 全称の語 (「必ず」「すべて」「収まる」「解消しない」など) | F (全称の主張は書く前に反例を挙げる) |
| 「正本は」にリンクが無い | B (正本の側を読み直す) |

全称の語の候補は手がかりであって規則ではない — 一致しても書いてよいし、一致しなくても全称の主張はありうる。観点 A・D・E は差分の形から導けないので提示しない。

## 前提

**Go が必要。** [triagecheck](../triagecheck/README.md) と同じく、バイナリは配らず `go run` で都度実行する (理由はそちらの「前提」)。

## 使い方

**`go run -C` でツールのモジュールに入って実行する。** diff は標準入力 (または `-diff <ファイル>`) で渡し、`-root` にリポジトリのルートの絶対パスを渡す (diff のパスをそこから解決する)。

```sh
# コミット前: ステージした Markdown の差分に当てる
git diff --cached -- '*.md' | go run -C <プラグインの展開先>/tools/nearedges . -root "$(pwd)" -hints

# コミットした後: そのコミットの差分に当てる
git show <sha> --format= -- '*.md' | go run -C <プラグインの展開先>/tools/nearedges . -root "$(pwd)" -hints
```

| フラグ | 必須 | 内容 |
| --- | --- | --- |
| `-root` | ✓ | リポジトリのルート (絶対パス) |
| `-diff` | | unified diff のファイル。既定は `-` (標準入力) |
| `-hints` | | 差分の種類に応じた観点 (B・C・F) も提示する |
| `-no-content` | | 範囲の本文を出さず、位置だけを出す |

出力は Markdown で、ファイルごとに範囲 (種類・行・見出し・変更行・理由) と、その本文を行番号つきで並べる (1 範囲 200 行で打ち切る)。**読んだ範囲は記録の `plans[].verification.near_edges` に書く** (様式の正本は [record-schema.md](../../skills/review-triage/references/record-schema.md))。

## 限界

- 表・箇条書き・見出し・コードフェンスの判定は行頭の記法で行う。HTML の表や、字下げの無い続きの行は範囲に入らない。
- リンク先の節はアンカーと見出しの照合 (見出しの文そのもの、または GitHub 風の slug) で引く。一致しなければ「アンカーに一致する見出しが無い」と出す。
- 同じ語を共有する遠くの辺 (別のファイル・別の節) は列挙しない。そちらは grep で辿る ([investigation.md](../../skills/review-triage-fix/references/investigation.md) の「語で探す」)。
