# ワーカーの起動と、その案内

**このファイルが、ワーカーを起動する手順と、人間にワーカーの起動を案内する文面の正本 (雛形)。** ワーカーを起動するのは 2 か所 — 回 1 の最初の依頼文を書いたとき ([round.md](round.md) の RL1 の手順 a の 8) と、`--resume` でワーカーが動いていないとき ([reentry.md](reentry.md) の「再入の手順」の 6)。どちらも下の「起動の手順」に従う。停止の報告 ([stops.md](stops.md) の「停止の報告に足すもの」) には、起動コマンドを書くだけで起動しない (続けるかどうかは人間が決める)。雛形はどれも、`{{…}}` を埋め、埋め残しが無いことを確かめてから出す。節を足したり消したりしない — 生成のたびに言い直すと、案内が回ごとに変わる。

## 起動の手順

1. **端末のツールが使えるかを確かめる。** 端末のツールは、Claude Desktop app の Terminal パネル (会話の横の端末) にタブを開いてコマンドを実行するツール (`run_in_terminal`) で、コマンドは利用者のログインシェルで、サンドボックスの外で実行され、ターンが終わっても実行され続ける。名前だけが示された遅延読み込みのツールなら、ツール ToolSearch で読み込んでから使う。使えなければ 3 に進む。
2. **起動してよいかを、人間に尋ねる** (blocking question tool。無ければ番号付きの選択肢)。ワーカーのモデル・effort・権限モード (`loop.yaml` の `worker` の値) と、下の「起動コマンドの組み立て」で組み立てたコマンドと、作業ツリーの絶対パス (`repo_dir`) を示し、「端末のタブで起動する」か「自分で起動する」かを選んでもらう。**「端末のタブで起動する」なら、端末のツールで、組み立てたコマンドをそのまま、作業ツリーをカレントディレクトリにして実行し** (タブの名前は `review-loop <周回 id>`)、下の「端末のタブで起動したときの知らせ」を出す。
   - **尋ねるのを省かない。** アプリの側でコマンドの実行を承認する仕組みがあっても、それに頼らない。ワーカーは依頼文ごとに `claude -p` を実行し、そのたびに費用がかかる。また、どのモデルで、いつ始めるかは人間が決める。
   - **コマンドを変えない。** モデル・effort・権限モードを含め、組み立てたとおりに実行する。人間が引数を変えたいとき (許可の一覧を足すなど) は「自分で起動する」を選んでもらう。
   - **起動したタブは閉じない。** ワーカーは終わるときに、応じた回の一覧を端末に表示する。人間がそれを読めるように残す。
   - **端末のツールがコマンドを実行しなかったら、その理由を示して 3 に進む。** ツールは、ASCII でない文字 (作業ツリーのパスに含まれた日本語など) を含むコマンドを受け付けない。アプリの側で実行が拒まれることもある。
3. **端末のツールが使えないか、人間が「自分で起動する」を選んだか、端末のツールがコマンドを実行しなかったら、下の「雛形」の案内を出す。**

**Bash ツールでは起動しない** — Bash ツールのコマンドはサンドボックスの中で実行されることがあり、その中から起動すると、レビュアの実行の Bash がどれも失敗する (正本は [worker.md](worker.md) の「起動の仕方」の「要るもの」)。バックグラウンドで起動しても、人間は様子を見られず、Ctrl-C で止めることもできない。

## 雛形

````markdown
**ワーカーを起動してください。** 周回 `{{loop_id}}` のレビューは、端末で起動するワーカーが行います。

1. 端末を開き、作業側と同じ作業ツリーに移動します。

   ```bash
   cd "{{repo_dir}}"
   ```

2. 次のコマンドでワーカーを起動します。**モデル・effort・権限モードを書き換えないでください** — 周回はこの値で始めたので、違う値で起動すると、各回の突き合わせでレビュー不成立として止まります。

   ```bash
   {{worker_command}}
   ```

- ワーカーは macOS でだけ動きます (ほかの OS では、起動してすぐに止まります)。
- ワーカーは端末に置いたままにしてください。依頼文が来るたびに、作業ツリーの使い捨ての複製を作ってその中でレビューし、周回を `/review-loop --end` で終えると、応じた回の一覧を表示して終わります。
- **周回の間は、作業ツリーを変えないでください** (編集・コミット・ブランチの切り替え)。レビューは複製の中で行いますが、ワーカーはレビューの前後で作業ツリーの HEAD と変更の有無を確かめるので、変えるとその回はレビュー不成立になって止まります。例外は、レビュー不成立で止まった周回を再開するために、報告の手順に従って設定を直してコミットするときです。
- 端末の `claude` は、Claude Desktop app とは別に認証が要ります。認証していなければ、先に端末で `claude` を 1 回起動してログインしてください。
- ワーカーを止めるときは、その端末で Ctrl-C を押します (レビュー中の回は、失敗として完了の印が書かれます。レビューを始める前の準備 (複製を作るなど) の途中なら印は書かれず、起動し直したワーカーがその回を初めからやり直します)。
````

雛形の箇条書きは、ワーカーの振る舞いのうち人間が知っておくことを、人間向けに言い直したもの。正本は [worker.md](worker.md) の「起動の仕方」の「要るもの」(macOS でだけ動くこと・端末のコマンド `claude` の認証)・「回の処理」(複製の中でレビューすることと、作業ツリーを変えるとレビュー不成立になること)・「終わり方」(周回の置き場にファイル `end` が現れたときと、Ctrl-C で止めたときの扱い) にある。**ワーカーの振る舞いを変えて、箇条書きに書いた事実が変わるときは、正本を直してから雛形を直す。**

## 起動コマンドの組み立て

`{{worker_command}}` は、`loop.yaml` の値で次の順に 1 行で組み立てる。

```
/bin/bash "<ワーカーのスクリプトの絶対パス>" "<置き場の絶対パス>" --model "<worker.model>" --effort <worker.effort> --permission-mode <worker.permission_mode> [--allowed-tools '<ツール>']... [--sandbox-allow-write '<パス>']... [--sandbox-allowed-domain '<ドメイン>']... --idle-minutes <worker.idle_minutes> --review-timeout-minutes <worker.review_timeout_minutes>
```

- **`bash` ではなく `/bin/bash` で起動する。** `bash` と書くと、環境変数 `PATH` で先に見つかる bash (Homebrew の 5.2 など) で動く。理由の正本は [worker.md](worker.md) の「起動の仕方」の「要るもの」。
- **ワーカーのスクリプトの絶対パス**は [SKILL.md](../SKILL.md) の「同梱のスクリプト」にある (`${CLAUDE_PLUGIN_ROOT}` が展開された絶対パス)。相対パスにしない — 人間が端末で `cd` した先で解決される。
- **`--permission-mode` は常に付ける** (理由の正本は [arguments.md](arguments.md) の「様式」。0.13.0 の案内のコマンドでワーカーを起動したときの扱いは、[worker.md](worker.md) の「止められたときの直し方」の「権限モードの指定の食い違い」の行)。
- `--allowed-tools` は、`worker.allowed_tools` の要素ごとに 1 つ付ける。**各要素を単一引用符で囲む** — `Bash(git diff:*)` の括弧と `*` をシェルが展開しないように。要素が単一引用符を含むときは `'\''` に置き換える。列が空なら付けない (ワーカーの既定の一覧を使う)。
- `--sandbox-allow-write` は `worker.sandbox_allow_write` の、`--sandbox-allowed-domain` は `worker.sandbox_allowed_domains` の要素ごとに 1 つ付け、`--allowed-tools` と同じく各要素を単一引用符で囲む。`~` で始まる要素も同じく囲む — `~` はシェルではなくワーカーがホームに展開するので、囲んでも意味は変わらない。列が空か、`loop.yaml` にキーが無ければ付けない。
- 各引数の意味の正本は [worker.md](worker.md) の「起動の仕方」。

## 端末のタブで起動したときの知らせ

````markdown
**ワーカーを端末のタブ `review-loop {{loop_id}}` で起動しました。** 周回 `{{loop_id}}` のレビューは、このワーカーが行います。

- ワーカーは macOS でだけ動きます (ほかの OS では、起動してすぐに止まり、周回はワーカーが動いていないとして止まります)。
- タブは閉じずに置いたままにしてください。タブを閉じると、ワーカーも終わります (レビュー中の回は、失敗として完了の印が書かれます)。周回を `/review-loop --end` で終えると、ワーカーは応じた回の一覧をタブに表示して終わります。
- **周回の間は、作業ツリーを変えないでください** (編集・コミット・ブランチの切り替え)。変えると、その回はレビュー不成立になって止まります。例外は、レビュー不成立で止まった周回を再開するために、報告の手順に従って設定を直してコミットするときです。
- 端末の `claude` は、Claude Desktop app とは別に認証が要ります。認証していなければ、レビューが失敗して周回が止まります。そのときは、別の端末 (Terminal パネルの別のタブなど) で `claude` を 1 回起動してログインしてから、`/review-loop --resume` で続けてください (ワーカーは止めなくて構いません)。
- ワーカーを止めるときは、そのタブで Ctrl-C を押します。
````

箇条書きの正本は、上の「雛形」の箇条書きと同じ ([worker.md](worker.md) の「起動の仕方」の「要るもの」・「回の処理」・「終わり方」)。
