# ワーカーの起動の案内

**このファイルが、人間にワーカーの起動を案内する文面の正本 (雛形)。** 使うのは 3 か所 — 回 1 の最初の依頼文を書いたとき ([round.md](round.md) の RL1 の手順 a の 8)、`--resume` でワーカーが居ないとき ([reentry.md](reentry.md) の「再入の手順」の 6)、停止の報告 ([stops.md](stops.md) の「停止の報告に足すもの」)。`{{…}}` を埋め、埋め残しが無いことを確かめてから出す。節を足したり消したりしない — 生成のたびに言い直すと、案内が回ごとに変わる。

## 雛形

````markdown
**ワーカーを起動してください。** 周回 `{{loop_id}}` のレビューは、端末で起動するワーカーが行います。

1. 端末を開き、作業側と同じ作業ツリーに移動します。

   ```bash
   cd "{{repo_dir}}"
   ```

2. 次のコマンドでワーカーを起動します。**モデルと effort を書き換えないでください** — 周回はこの値で始めたので、違う値で起動すると、各回の突き合わせでレビュー不成立として止まります。

   ```bash
   {{worker_command}}
   ```

- ワーカーは端末に置いたままにしてください。依頼文が来るたびにレビューし、周回を `/review-loop --end` で終えると、応じた回の一覧を出して終わります。
- **周回の間は、作業ツリーを変えないでください** (編集・コミット・ブランチの切り替え)。変えると、その回はレビュー不成立になって止まります。
- 端末の `claude` は、Claude Desktop app とは別に認証が要ります。認証していなければ、先に端末で `claude` を 1 回起動してログインしてください。
- ワーカーを止めるときは、その端末で Ctrl-C を押します (レビュー中の回は失敗として完了の印が書かれます)。
````

## 起動コマンドの組み立て

`{{worker_command}}` は、`loop.yaml` の値で次の順に 1 行で組み立てる。

```
bash "<ワーカーのスクリプトの絶対パス>" "<置き場の絶対パス>" --model "<worker.model>" --effort <worker.effort> [--permission-mode <worker.permission_mode>] [--allowed-tools '<ツール>']... --idle-minutes <worker.idle_minutes> --review-timeout-minutes <worker.review_timeout_minutes>
```

- **ワーカーのスクリプトの絶対パス**は [SKILL.md](../SKILL.md) の「同梱のスクリプト」にある (`${CLAUDE_PLUGIN_ROOT}` が展開された絶対パス)。相対パスにしない — 人間が端末で `cd` した先で解決される。
- `--permission-mode` は、`worker.permission_mode` が `default` でないときだけ付ける。
- `--allowed-tools` は、`worker.allowed_tools` の要素ごとに 1 つ付ける。**各要素を単一引用符で囲む** — `Bash(git diff:*)` の括弧と `*` をシェルが展開しないように。要素が単一引用符を含むときは `'\''` に置き換える。列が空なら付けない (ワーカーの既定の一覧を使う)。
- 各引数の意味の正本は [worker.md](worker.md) の「起動の仕方」。

## 端末のツールがあるとき

Claude Desktop app で、端末のタブでコマンドを走らせるツールが使えるときは、このコマンドを端末のタブで起動することを人間に提案してよい。**起動するかどうかは人間が決め、承認を得てから起動する。モデルと effort はコマンドのとおりで、変えない** (どのモデルで、いつ始めるかは人間が決める)。承認が無ければ、上の案内を出すだけにする。
