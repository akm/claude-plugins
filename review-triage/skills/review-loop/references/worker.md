# ワーカー

**このファイルが、ワーカー (スクリプト `review-triage/scripts/review-loop-worker.sh`。人間が端末で起動し、依頼文ごとに `claude -p` を走らせるプロセス) の振る舞いの正本。** スクリプトはこの文書のとおりに実装し、テスト `review-triage/tests/test_review_loop_worker.py` が確かめる。ワーカーが書くファイル (`worker.yaml`・完了の印) の様式の正本は [loop-files.md](loop-files.md) で、ここでは言い直さない。

**ワーカーは、レビュアの実行 (`claude -p` の 1 回) 以外の判断をすべてスクリプトで行う。** 起動時の確認・依頼文の探索・HEAD と作業ツリーの確認・上限・結果の確認・完了の印・終わり方は決定的なコードで、LLM の手順書に頼らない。

## 起動の仕方

```
review-loop-worker.sh <周回の置き場の絶対パス> --model <指定> --effort <値>
    [--permission-mode <値>] [--allowed-tools <ツール>]... [--idle-minutes <分>]
    [--review-timeout-minutes <分>] [-- <claude に渡す追加の引数>...]
```

| 引数 | 意味 | 省略時 |
| --- | --- | --- |
| `<周回の置き場の絶対パス>` | 周回の置き場。**絶対パスに限る** — 相対パスは起動した端末の cwd で解決され、作業側が意図した置き場に届かないことがある | 省略できない |
| `--model <指定>` | レビュアの実行のモデル (`claude -p --model` にそのまま渡す) | **省略できない** — どのモデルでレビューするかは人間が決める |
| `--effort <値>` | レビュアの実行の effort (`low` / `medium` / `high` / `xhigh` / `max`) | **省略できない** (同上) |
| `--permission-mode <値>` | レビュアの実行の権限モード。`bypassPermissions` は受け付けない (下の「レビュアの実行の権限」) | `default` |
| `--allowed-tools <ツール>` | レビュアの実行に許すツール。繰り返して指定でき、**1 回でも指定すれば既定の一覧を置き換える** | 下の「既定の許可の一覧」 |
| `--idle-minutes <分>` | 印の無い依頼文が無いまま待つ上限 | 180 |
| `--review-timeout-minutes <分>` | レビュアの実行 1 回の上限 | 60 |
| `-- <引数>...` | `claude -p` の末尾にそのまま渡す (通し確認で `--plugin-dir` や `--settings` を渡す) | 無し |

**ワーカーは設定ファイル (`config.json`) を読まない。** 値はすべて引数で受け、作業側が設定の `review_loop` 節の値を案内のコマンドに埋める (キーの正本は [project-config.md](../../review-triage/references/project-config.md) の「`review_loop`」)。プラグインの展開先と利用者のリポジトリは別の場所にあり、スクリプトから設定を探すと、どのリポジトリの設定を読むかの基準を取り違える。

| 終了コード | 意味 |
| --- | --- |
| 0 | `end` を見て終わった |
| 124 | 印の無い依頼文が無いまま `--idle-minutes` が過ぎた。**周回は終わっていない** — 同じコマンドで起動し直せる |
| 2 | 引数の誤り・起動時の確認が通らない・動いている他のワーカーが居る |
| 128 + シグナル番号 | 割り込み (INT なら 130、TERM なら 143、HUP なら 129) |

**要るもの**: bash (macOS の `/bin/bash` 3.2 で動く)・git・python3 (レビュアの実行を専用のプロセスグループで起動するのと、ログを読むのに使う)・`claude` (端末の `claude` は Claude Desktop app とは別に認証が要る)。

## サポートする配置

| 配置 | 扱い |
| --- | --- |
| 作業側と同じマシンの、同じ作業ツリー | サポートする。作業ツリーの中のサブディレクトリで起動してもよい (ルートに解決して比べる) |
| 同じリポジトリの別の worktree | サポートしない。起動時の確認で「別の worktree」として `unavailable` にする — レビュアの実行が見る HEAD と作業ツリーが、作業側のものと違う |
| 別のクローン・別のリポジトリ | サポートしない。「別の作業ツリー」として `unavailable` にする |
| 別のマシン | サポートしない。置き場の共有と、他のワーカーの判定 (`kill -0`) が同じマシンを前提にしている |

## 起動時の確認

**上から順に確かめる。** 1 だけは通らなくても `worker.yaml` に触れない (動いている他のワーカーの状態を上書きしないため)。2 以降は、最初に通らなかった項目を理由に `worker.yaml` を `unavailable` で書いて、終了コード 2 で終わる。

| 順 | 状況 | 確かめ方 | 通らないときの扱い |
| --- | --- | --- | --- |
| 1 | 動いている他のワーカーが居ない | `worker.yaml` の `state` が `idle` / `reviewing`・ファイルの更新時刻が 30 秒以内・`pid` のプロセスが動いている (`kill -0`) の **3 つがすべて成り立てば、居る** | `worker.yaml` に触れず、PID と止め方 (そのワーカーの端末で Ctrl-C か `kill -TERM <PID>`) を標準エラーに出して終了コード 2 |
| 2 | 置き場に `loop.yaml` があり、`repo_dir` が読める | ファイルの有無と、トップレベルの `repo_dir` の行 | `unavailable` |
| 3 | 作業側と同じ作業ツリーで起動した | `git rev-parse --show-toplevel` を実体パス (`cd` して `pwd -P`) に解決したものが、`repo_dir` の実体パスと一致する | 一致しなければ、`git rev-parse --git-common-dir` の実体パスが同じなら「別の worktree」、違えば「別の作業ツリー」を理由に `unavailable` |
| 4 | HEAD が読める | `git rev-parse --short HEAD` | `unavailable` |
| 5 | 周回が終わっていない | 置き場に `end` が無い | `unavailable` |
| 6 | 使うコマンドがある | `command -v claude` と `command -v python3` | `unavailable` |

1 の判定に更新時刻を加えるのは、`kill -9` で消えたワーカーの PID が別のプロセスに再利用された場合に、居ないワーカーを居ると判定しないため。名前や乱数の値でワーカーを見分けない。

すべて通れば `worker.yaml` を `idle` で書き、更新時刻を 5 秒おきに進める背景の処理を始める。

## 回の処理

1. **探す**: 5 秒おきに、置き場の `review-request-<識別子>.md` のうち完了の印 (`delivered-<識別子>.yaml`) が無いものを、識別子の順で 1 つ選ぶ。一時名 (`.` で始まる名前) は見ない。**レビュアの実行の間に置き場に現れた依頼文は、この起動の間は選ばない** — レビュアの実行が置いたものとみなす (作業側は、ワーカーが印を書くまで次の依頼文を書かない)。
2. **受け取る**: `worker.yaml` を `reviewing` と識別子にする。
3. **依頼文を確かめる**: 埋め残しの `{{` が無い、`## 出力様式` の行がある、`head: "<SHA>"` の行がある。通らなければ、レビュアの実行を起動せずに `failed` の印を書く。
4. **HEAD と作業ツリーを確かめる**: 依頼文の `head` と現在の HEAD が同じコミットを指し (`git rev-parse` で完全な SHA にして比べる)、`git status --porcelain` が空であること。通らなければ、レビュアの実行を起動せずに `failed` の印を書く。
5. **控える**: 置き場のファイルの一覧と各ファイルの更新時刻 (`worker.yaml`・その回の結果・その回のログを除く)。結果が既にあれば、その更新時刻と大きさ。
6. **レビュアの実行を起動して待つ** (下の「レビュアの実行」)。
7. **確かめる**: 下の表の項目を確かめる。1 つでも当たれば `failed` で、当たった項目をすべて `error` に書く (`; ` で区切る)。
8. **ログを読む** (下の「ログの読み方」)。
9. **完了の印を書き** (一時名から改名)、`worker.yaml` を `idle` に戻す。**印を書かずに次の依頼文に進まない。**

| 項目 | 確かめ方 | `error` に書くもの |
| --- | --- | --- |
| 依頼文の形 (手順 3) | 上のとおり | `request malformed (unfilled placeholder)` / `request malformed (no output format section)` / `request malformed (no head line)` |
| HEAD (手順 4) | 上のとおり | `head mismatch (expected <依頼文の head>, actual <HEAD>)` |
| 作業ツリー (手順 4) | 上のとおり | `tree not clean (<汚れたファイルの一覧>)` |
| 結果がある | その回の結果のファイルがある | `no result` |
| 結果がこの実行で書かれた | 手順 5 で控えた更新時刻と大きさから変わった (実行の前には無かった場合は問わない) | `no result (the file is from an earlier run)` |
| 結果の形 | `findings:` の行がある | `no findings key` |
| 結果の `run_id` | トップレベルの `run_id` が識別子と一致する | `run_id mismatch (expected <識別子>, actual "<値>")` |
| HEAD が不変 | 実行の前後で HEAD が同じコミットを指す | `head changed (before <前>, after <後>)` |
| 作業ツリーが clean | 実行の後の `git status --porcelain` が空 | `tree not clean (<汚れたファイルの一覧>)` |
| 置き場が不変 | 手順 5 で控えた一覧と更新時刻から変わっていない (同じものを除いて比べる) | `loop dir modified (<変わったファイルの一覧>)` |
| 上限 | `--review-timeout-minutes` を越えた | `timeout` |
| 割り込み | INT / TERM / HUP を受けた | `interrupted` |

上限と割り込みの回は、結果の 4 項目 (ある・この実行で書かれた・形・`run_id`) を確かめない — 止めた実行の結果は使わない。HEAD・作業ツリー・置き場は確かめる (止める前にレビュアの実行が変えていれば、それも人間が片付けるものなので `error` に並べる)。**レビュアの実行の終了コードは条件にしない** — 印の `exit_code` に残すだけで、使えるかは結果の形と前後の状態で決める。

**置き場の比較は、作業ツリーの確認とは別に行う。** 置き場は git に無視されているので、`git status` では検出できない。レビュアの実行が依頼文や `end` を置くと、ワーカーや作業側がそれに従ってしまう。

## レビュアの実行

```
claude -p "<プロンプト>" --model <指定> --effort <値> --permission-mode <値> \
  --allowedTools <許可の一覧>... --disallowedTools AskUserQuestion \
  --output-format stream-json --verbose [<追加の引数>...]
```

- **プロンプトは固定の 1 文「依頼文 `<依頼文の絶対パス>` のとおりに作業し、結果を依頼文が指す出力先に書く。」で、依頼文の中身を写さない。** 依頼文はレビュアが読む前提で書かれている (雛形の冒頭)。写すと、貼り方が回ごとに変わる元の問題 ([review-request.md](../../review-triage/references/review-request.md) の「依頼文はファイルに書き出し、パスだけを渡す」) に戻る。
- **`AskUserQuestion` は `--disallowedTools` で外す。** `-p` は人間に問えないので、外しておくとレビュアは問わずに進む (外したツールはレビュアに示されない)。
- cwd は作業ツリーのルート、標準入力は `/dev/null`。標準出力と標準エラーは置き場の `<識別子>.log` にそのまま書く。
- **専用のプロセスグループで背景に起動し、`wait` で終わりを待つ。** 前景で待たないのは、bash が前景のコマンドを待っている間は trap (シグナルを受けたときの処理) をそのコマンドが終わるまで遅らせるためと、専用のプロセスグループにしないと端末の Ctrl-C がワーカーとレビュアの実行に同時に届き、止める順序を制御できないため。待っている間も更新時刻を進める。
- **上限を越えたとき・割り込みを受けたときは、プロセスグループ全体に TERM を送り、5 秒後に残っていれば KILL を送り、すべて止まったことを確かめてから印を書く。** `claude -p` が起動した子孫 (Bash ツールの子や sub-agent) を残さない。
- ワーカー自身は git の状態を変えない。レビュアの実行が変えた場合は、上の表の確認で検出する。

`-p` の中でも Skill と Agent のツールは使える。レビュアの実行にも、利用者の設定・フック・インストール済みのプラグイン・CLAUDE.md が効く。

## レビュアの実行の権限

**既定は、権限モード `default` と、下の既定の許可の一覧と、その回の結果ファイル 1 つへの書き込みの許可。** 依頼文は読み取りを前提に書かれているので、既定のレビューは書き込みを要しない。

既定の許可の一覧:

- git の読み取り — `Bash(git diff:*)`・`Bash(git log:*)`・`Bash(git show:*)`・`Bash(git status:*)`・`Bash(git rev-parse:*)`・`Bash(git merge-base:*)`・`Bash(git ls-files:*)`・`Bash(git blame:*)`・`Bash(git cat-file:*)`・`Bash(git grep:*)`
- ファイルの読み取り — `Read`・`Grep`・`Glob`
- スキルと sub-agent — `Skill`・`Agent`

**結果ファイルへの書き込みの許可 `Edit(//<結果の絶対パス>)` は、ワーカーが毎回足す** (`--allowed-tools` で一覧を置き換えたときも)。`//` の後に、ルートからのパスを続ける (Claude Code の許可の規則で、絶対パスを表す書き方)。結果のパスは識別子から導出する。

- **`acceptEdits` を既定にしない。** `acceptEdits` は許可の一覧と関係なく作業ディレクトリ内の編集をすべて自動で許可するので、git に無視されるファイル (記録 `tmp/review-triages/*.yaml` やファイル `.claude/settings.local.json` など) への書き込みが検出されないまま `ok` になる。依頼文の雛形が許すプローブ (一時的な変更と revert) を許したいときは、人間が `--permission-mode acceptEdits` を明示して起動する。
- **`bypassPermissions` は受け付けない** (引数の誤りとして終了コード 2)。レビュアの実行が結果ファイルの外を書けてしまう。
- **`-p` は許可の問い合わせに答えられないので、許可の一覧に無いツールの呼び出しは拒否されるだけで、レビュアは実行を続ける。** 調べられなかった範囲の指摘が欠けたまま結果が書かれるので、拒否の件数とツール名を完了の印の `permission_denials` に書き、作業側がレビュー不成立 (RA1) として止める。人間は拒まれたツールを見て、`--allowed-tools` を足して起動し直す。
- 利用者の `settings.json` の許可も効く。
- 既定の一覧は、通し確認で拒まれたツールを数えて直す。

## ログの読み方

**ログは 1 行ずつ JSON として読み、読めない行 (フックの出力や標準エラーの行など) は飛ばす。** `parent_tool_use_id` が空でない行 (レビュースキルが起動した sub-agent の行) は、どの項目にも使わない。

| 印の項目 | 読み方 | 読めないとき |
| --- | --- | --- |
| `model.effective` | `type` が `system` で `subtype` が `init` の行のうち最初のものの `model` (モデル ID) から、先頭の `claude-` を除いたもの | `unknown` |
| `skill_called` | `type` が `assistant` の行の `message.content` にある `tool_use` のうち、`name` が `Skill` のものがあれば `true`、無ければ `false`。**ツールの結果 (`type` が `user` の行の `tool_result`) の中身は読まない** — レビュー対象のファイルに `Skill` やモデル名の文字列が含まれていても判定が変わらないようにするため | `assistant` の行が 1 つも無ければ `unknown` |
| `permission_denials` | 最後の `type` が `result` の行の `permission_denials` (配列) の要素数と、各要素の `tool_name` (重複を除く) | `result` の行が無いか、`permission_denials` が配列でなければ件数を `unknown` |

**effort はログのどの行にも出ない。** 印の `effort` はワーカーに渡した値で、実行時の値は確かめられない。

## 終わり方

- **`end` を見たら**、`worker.yaml` を `left` にし、この起動で応じた回の一覧 (識別子・`status`・モデル・effort・所要時間・`error`) を標準出力に出して、終了コード 0 で終わる。`end` は依頼文を探す前に見る。レビュアの実行中に `end` が現れたら、その回を終えて印を書いてから見る (その回は置き場が変わったとして `failed` になる)。
- **印の無い依頼文が無いまま `--idle-minutes` が過ぎたら**、`worker.yaml` を `expired` にし、周回は終わっていないことと同じコマンドで起動し直せることを出して、終了コード 124 で終わる。期限は最後に回を終えた時刻 (無ければ起動した時刻) から数える。
- **割り込み (INT / TERM / HUP。HUP は端末を閉じたとき) を受けたら**、レビュアの実行中ならそれを止めて `failed`・`interrupted` の印を書き、更新時刻を進める処理を止め、`worker.yaml` を `left` にして終わる。
- **`kill -9` で消されたときは trap が動かない。** 更新時刻を進める背景の処理は、周期ごとにワーカーのプロセスが居るか (終わったのに回収されていないプロセスは居ないとみなす) を確かめ、居なければ自分も終わる。`worker.yaml` の更新時刻が止まるので、作業側は停滞として気づく。起動し直すと、印の無い依頼文から続ける。

## このワーカーが検出しないもの

- **結果の中身が正しいか** — 確かめるのは形 (`findings` と `run_id`) と前後の状態だけ。
- **effort が実際に効いたか** — ログに出ないので、渡した値を印に残すだけ。
- **置き場と作業ツリーの外への書き込み** — 権限の既定で防ぐ。`acceptEdits` で起動したときに git に無視されるファイルへ書かれても、検出できない。
