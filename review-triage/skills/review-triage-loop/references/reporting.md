# 報告の形

**このファイルが `review-triage-loop` の報告の正本。** 各回の中の報告 (判定の内訳・保留の提示・修正した問題) は `review-triage` と `review-triage-fix` が持つ — ここが定めるのは、**周回そのものについて何を伝えるか**である。

## 必ず出すもの

1. **止まった理由** — どの停止ノード (S2〜S4) で止まったか (正本は [loop-flow.md](loop-flow.md))。
2. **回った回数と上限** — 「3 回 / 上限 5 回」の形。この起動でレビューを 1 回も走らせずに止まった (回した回数が 0) ときは「0 回 / 上限 5 回」と書き、推移は出さない。
3. **採択件数の回ごとの推移** — 下記。
4. **周回の条件** — レビュースキル・そのオプション・実効モデル (定義の正本は [review-invocation.md](review-invocation.md) の「実効モデル」)。手順 1 (決定表 G0) で報告したものと同じ値。
5. **残っているもの** — 未着手 (`status: pending`) の問題があれば、その回と識別子。**止まった理由を問わず出す** — 周回の後に残ったものは次の周回か人間が引き継ぐので、報告に無いと引き継ぎ先が知る手段が無い。

## 採択件数の推移

**周回の結果を読むための中心的な材料。** 止まった理由だけでは、収束に向かっていたのか減らないまま止まったのかが分からない。

回ごとに、採択・保留・却下の件数を並べる。

```
回 1 (全量):   採択 6 / 保留 1 / 却下 12
回 2 (増分):   採択 3 / 保留 0 / 却下 4
回 3 (増分):   採択 0 / 保留 1 / 却下 2   → 収束
```

**件数は記録 YAML から数える。** 各回の報告の文面から拾わない — 要約は取りこぼしうる。

## 止まった理由ごとに足すもの

**正本は [loop-flow.md](loop-flow.md) の決定表の停止ノード (S2〜S4) の「報告に書くもの」。** ここには写さない — 写すと、止まる条件を足したときに片方だけが古くなる。

## 書かないもの

- **周回の内部の進み方** — どの sub-agent をいつ立てたか、JSON をどう写したかなどは、読み手が次に何をするかに関係しない。
- **各回の判定の詳細** — `review-triage` が回ごとに報告済みで、記録にも残っている。周回の報告で繰り返さない。
