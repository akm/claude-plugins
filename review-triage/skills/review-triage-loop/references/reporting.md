# 報告の形

**このファイルが `review-triage-loop` の報告の正本。** 各回の中の報告 (判定の内訳・保留の提示・修正した問題) は `review-triage` と `review-triage-fix` が持つ — ここが定めるのは、**周回そのものについて何を伝えるか**である。

## 必ず出すもの

1. **止まった理由** — 終了条件のどれに当たって止まったか (条件の一覧と判定の正本は [SKILL.md](../SKILL.md) の手順 3)。
2. **回った回数と上限** — 「3 回 / 上限 5 回」の形。
3. **採択件数の回ごとの推移** — 下記。
4. **周回の条件** — レビュースキル・そのオプション。手順 1 で報告したものと同じ値。

## 採択件数の推移

**周回の結果を読むための中心的な材料。** 止まった理由だけでは、収束に向かっていたのか減らないまま止まったのかが分からない。

回ごとに、採択・保留・却下の件数を並べる。

```
回 1 (全量):   採択 6 / 保留 1 / 却下 12
回 2 (増分):   採択 3 / 保留 0 / 却下 4
回 3 (増分):   採択 0 / 保留 1 / 却下 2   → 収束
```

**件数は記録 YAML から数える。** 各回の報告の文面から拾わない — 要約は取りこぼしうる。

## 止まった理由ごとに足すもの

### 収束

採択が 0 件になった回を示す。**「欠陥が無い」とは書かない** — そのレビュースキル・そのモデル・その範囲で指摘が出なかった、という事実に留める ([SKILL.md](../SKILL.md) の「このスキルが検出しないもの」)。

保留が残っていれば件数を出す。保留は人間の判断待ちで、収束しても消えない。

### 検知

`recurrence` の条件と根拠を出し (形の正本は [recurrence-detection.md](../../review-triage/references/recurrence-detection.md))、**俯瞰 (`review-triage-fix` の手順 2) を案内する。勝手に呼ばない** — 俯瞰は人間と図で確かめる作業である。

### 選択待ち

`status: awaiting-human` の問題と、その `options` (選択肢とトレードオフ) を出す。**どの回のものかを添える** — 過去の回で返したまま回答が無いものが含まれうる。

### 上限

**推移を示したうえで、継続するか俯瞰に移るかを人間に問う。**

問い方は推移によって変える。

- **減っている** (採択が回ごとに減っている) — あと数回で収束する見込みがあることを示し、継続するか尋ねる。
- **減っていない** (採択が横ばい、または増えている) — 収束していないことを示す。**この場合は俯瞰を先に勧める** — 同じ型の指摘が続いている可能性が高く、`recurrence` が捉え損ねた状態でありうる。回を重ねても同じ型の指摘に応え続けることになる。

**どちらの場合も、勝手に周回を再開しない。**

## 書かないもの

- **周回の内部の進み方** — どの sub-agent をいつ立てたか、JSON をどう写したかなどは、読み手が次に何をするかに関係しない。
- **各回の判定の詳細** — `review-triage` が回ごとに報告済みで、記録にも残っている。周回の報告で繰り返さない。
