# review-triage-loop: レビューから修正までの周回

レビューの起動・[review-triage](../review-triage/SKILL.md)・[review-triage-fix](../review-triage-fix/SKILL.md) を 1 周として、**終了条件に当たるまで繰り返す。** 成果物は周回の結果の報告であって、判断でも修正でもない — 判断は `review-triage`、修正は `review-triage-fix` が持つ。

**このスキルは 2 つのスキルを呼ぶだけで、それらの中身を代行しない。** 採否を決めたり、修正の方針を決めたりはしない。

## 前提知識

- **周回は必ず止まる。** 上限に達したら、採択が残っていても止める (上限を設ける理由の正本は [project-config.md](../review-triage/references/project-config.md) の「`loop`」)。
- **選択待ちは、既存のスキルが人間の判断を求めて止まった結果である。** 周回がそれを越えて進むと、判断を求めた意味が消える。上限はそれとは別で、収束しない周回を止めるためにこのスキルが持つ関門である。
- **モデルは周回ごとに選べる (指定が効く経路に限る — 経路ごとの効き方の正本は [references/review-invocation.md](references/review-invocation.md) の「G0 での解決」)。** 1 つの周回はどの回も同じモデルで走らせる (設定と引数は周回全体に 1 つの値を持つ) が、周回をまたげば変えてよい — 記録は回ごとに `model` を持つので、後から粒度の違いを比較できる。使い分けの目安 (実害系の検出と、収束を確かめる回で向くモデルが違う) は [record-schema.md](../review-triage/references/record-schema.md) の「生成サマリの読み方」が正本。**周回の途中で勝手に切り替えない** — 切り替えるなら、いったん止めて人間が次の周回の条件として指示する。目安に従って使い分ける手順は、まず 1 つの周回を止まるまで回し、止まった後に `--model` を変えて次の周回を起動する (例: 収束の仕上げだけ別のモデルで回す)。指定が効かない経路では、この手順を踏んでも実効モデルは変わらない。

## 手順

**周回の順序・分岐・優先・止まる条件は [references/loop-flow.md](references/loop-flow.md) が正本。** このファイルでは言い直さない — 以下、ノード ID (G0・G2・G3・L1・L2・J2・J4・J5・F1・S2〜S4) はそこを指す。

1. **設定と引数を読む** (G0): `.claude/akm-claude-plugins/review-triage/config.json` の `loop` を読み、引数で上書きする (キーと既定値の正本は [project-config.md](../review-triage/references/project-config.md) の「`loop`」。引数の様式は [references/arguments.md](references/arguments.md))。
   - **`review_skill` が引数でも設定でも未設定なら、人間に尋ねる** (「未設定」の定義の正本は [project-config.md](../review-triage/references/project-config.md))。推測して決めない。
   - 決まった条件を周回の開始前に報告する (書くものは決定表の G0)。**どの条件で回るかを、回り始める前に人間が知っている状態にする。**
2. **入口の関門** (G2・G3): 記録 YAML を読み (置き場は設定の `record_dir`、ファイルは `<ブランチ名>.yaml`)、図の順に判定する。各ノードの条件・行き先・止まるときの報告は、図と決定表が正本。
3. **周回** (L1 → S2〜S4): 図に従って回す。各ノードで行うことと見る場所は決定表のとおり。**各回の冒頭で、いま何回目かと上限を報告する** (L1)。
4. **報告** (S2〜S4): 止まった理由と、周回で何が起きたかを出す。全体の形は [references/reporting.md](references/reporting.md)、止まった理由ごとに足すものは決定表の S2〜S4 が正本。**採択件数の回ごとの推移を必ず出す** — 収束に向かっていたのか、減らないまま止まったのかは、件数の推移にしか現れない。

## 原則

- **このスキルは判断も修正もしない。** 呼ぶだけ。判断を代行すると、`review-triage` の記録に残らない判断が生まれる。
- **上限に達したら止める。** 「あと 1 回で終わりそう」でも延長しない。延長の判断は人間が行う。
- **人間に返した状態を越えて進まない。** 選択待ちは、既存のスキルが人間の判断を求めて止まった結果である。
- **周回が条件を勝手に変えない。** 上限・レビュースキル・オプション・モデルは、手順 1 で決めたものを使う。**変えてよいのは人間が指示したときだけ** — 周回が回ごとに判断して切り替えると、指摘の減り方がモデルの違いによるものか収束によるものかを、人間が読み解けなくなる。

## このスキルが検出しないもの

- **採否の判断が正しいか** — `review-triage` の結果をそのまま使う。
- **修正の内容が正しいか** — `review-triage-fix` の検証に委ねる。
- **収束したことが「欠陥が無い」ことを意味するか** — 意味しない。採択が 0 件になったのは、そのレビュースキル・そのモデル・その範囲で指摘が出なかったということである。
