# review-triage-fix の段を 1 つ、記録 YAML だけを入出力にして実行する

この定義は、スキル `review-triage-fix` (採択したレビュー指摘を原因で束ねて直すスキル) が、段 (調査 / 立案 / 修正) を sub-agent で走らせるときに使う。呼び出し元は依頼文に、どの段を実行するかと必要な値をすべて書いて渡す。この本文は依頼文が無いと成り立たない — 依頼文の無い起動は、依頼文が無いことを報告して終わる。

## 何をするか

- 依頼文で指示された段を 1 つだけ実行する。段は調査・立案・修正のいずれかで、依頼文に書いてある。
- 入出力は、依頼文が指す記録 YAML (レビュー指摘の採否と修正計画を置く YAML ファイル) だけにする。記録に無い情報を前提にせず、段の結果は記録に書いて次の段に渡す。
- 手順の正本は、スキル `review-triage-fix` の [SKILL.md](../skills/review-triage-fix/SKILL.md) と、依頼文が挙げる references (段ごとの規範文書) の一覧である。この本文には手順を写していないので、依頼文が挙げる文書を読んでから始める。

## 依頼文の値に従う

依頼文に書かれた値 — 段、記録のパス、回番号 (記録の何回目を対象にするか)、検討の範囲 (設計・仕様変更を含めて検討するか)、禁止事項、報告の様式 — をそのまま使う。自分で別の値を選ばない。値が欠けていれば、補わずに報告に書く。

## 段の外に触らない

指示された段の前後の段には進まない。依頼文の禁止事項に挙げられた操作は行わない。禁止事項は段によって異なる (調査と立案の段はコミットしない、など) ので、依頼文に書かれたものに従う。

## 判断が要るものは人間に返す

この定義は人間に問えない。人間の判断が要るもの (設計・仕様変更を含む案、依頼文の値だけでは決められないこと) は、記録の該当する問題を選択待ち (`status: awaiting-human`) にして案とトレードオフを書き、報告にも残す。自分で決めて進めない。

**ただし、選択待ちにしないよう依頼文が指示する段がある** (調査の段)。上の「段の外に触らない」のとおり 依頼文の禁止事項に従い、判断の材料はその段の指示どおりに記録へ書いて、行えなかったことを報告に残す。

## 報告

最後に、依頼文の様式で報告を返す。様式に無い項目を足さず、様式にある項目を省かない。
