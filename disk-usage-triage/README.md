# disk-usage-triage

ディスクの空きが足りないときに、利用者が設定したディレクトリを `du -d 1` と同じ深さで調べ、容量の大きい項目を、消してよいかの判定 (消してよい・確認が要る・残す) と一緒に一覧で示すプラグインです。利用者が選んだ項目から削除のシェルスクリプトを作り、利用者が中身を確認してから端末で実行します。Claude は削除のシェルスクリプトを実行しません。要望は Issue [#310](https://github.com/akm/claude-plugins/issues/310)、設計は計画 [docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md](../docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md) にあります。

**作成中**です。今の版 (0.5.0) のスキル `triage` は、設定 (調べるディレクトリ・プロジェクトのディレクトリ・時間の上限) を作る・変えること、調べるディレクトリを調べて判定と一緒に一覧で示すこと、項目の下の階層を一覧にすること、判定表に無い項目を Claude が調べて判定を記録すること、消す項目を選ぶことと、記録 (利用者と Claude が決めた判定を、次回の判定に使うために保存したもの) を見る・足す・消すことを行います。hook は、Claude が削除のシェルスクリプトを実行することと、書き換えることを拒否します (節「[hook](#hook)」)。削除のシェルスクリプトの作成・削除の後の比較・asdf と Docker とアプリの worktree の一覧は、計画の実装の単位ごとに足します。

## 使えるスキル

| スキル | すること |
| --- | --- |
| [triage](skills/triage/SKILL.md) | 設定が無ければ、調べるディレクトリとプロジェクトのディレクトリを質問して保存する。依頼があれば、設定を変える。調べるディレクトリを調べて、項目を判定と一緒に一覧で示し、項目の下の階層の一覧・判定表に無い項目の調査・消す項目を選ぶことを行う。記録を示して消すことと、利用者が残すと言った対象を記録することも行う |

## hook

プラグインを有効にしたすべてのセッションで、hook `PreToolUse` (Claude がツールを実行する前に、Claude Code が実行する hook。ファイル [hooks/hooks.json](hooks/hooks.json)) が、Claude が削除のシェルスクリプトを実行することと、書き換えることを拒否します。削除のシェルスクリプトは、利用者が中身を確認してから端末で実行するもので、Claude は実行しません。

| ツール | 拒否するもの |
| --- | --- |
| Bash ツールと、アプリの Terminal パネルにコマンドを送る MCP ツール `mcp__terminal__run_in_terminal` | 入力の文字列 (コマンド・タブを開くディレクトリなど) のどれかが、下の文字列のどれかを含むもの。実行するコマンドか、読み取るだけのコマンドかを区別しません |
| Write・Edit・MultiEdit・NotebookEdit ツール | 書き込むファイルのパスが、下の文字列のどれかを含むもの。書く内容は検査しません |

拒否する文字列は、次の 3 つです。

- `disk-usage-triage/runs` (保存先のディレクトリの下の、トリアージのファイルを保存するディレクトリ `runs`)
- 保存先のディレクトリの下の `runs` の絶対パス (環境変数 `DISK_USAGE_TRIAGE_HOME` で保存先のディレクトリを変えたときのため)
- 削除のシェルスクリプトのファイル名 `disk-usage-triage-delete.sh`

hook は文字列しか見ないので、パスを別の形で書いたコマンド (変数・相対パス・別のファイルに書いたコマンド) は拒否できません。また、次のときは hook が判定できず、Claude Code はツールをそのまま実行します。このとき、Claude Code は hook の誤りを会話に示します。

- コマンド `python3` が起動しないとき。たとえば、`python3` が asdf の shim で、セッションの作業ディレクトリのファイル `.tool-versions` が指す Python の版が消えているとき。
- `python3` が 3.11 より古いとき。
- hook の入力を読めないとき。

hook が拒否できなかったときも、削除のシェルスクリプトは、冒頭で Claude Code から実行されたかを確認し、端末から項目の数を入力させるので、Claude が実行しても何も消さずに終了します (計画の R38。削除のシェルスクリプトを作る機能は、後の版で足します)。

## 前提

- macOS の Claude Desktop の Code タブのセッションで使います。
- Python 3.11 以上 (標準ライブラリだけを使います)。スクリプトはコマンド `python3` で実行するので、`python3` が 3.11 より古い版を指すと、スクリプトは何もせずに終了し、スキルは版が古いことを示します。

## ファイル

設定などのファイルは、ディレクトリ `~/.claude/disk-usage-triage/` (保存先のディレクトリ) に保存します。中身はこのマシンのパスを指すので、ほかのマシンと同期・共有しないでください。ファイルの様式は [references/files.md](references/files.md) にあります。

## テスト

```bash
python3 -m unittest discover -s disk-usage-triage/tests
```

## このリポジトリで開発するとき

このプラグインの hook を有効にしたセッションでこのリポジトリを開発すると、節「[hook](#hook)」の 3 つの文字列を含むコマンドが拒否されます。次のように作業します (計画の KTD8)。

- 文字列を含む文 (コミットメッセージ・PR 本文など) は、ファイルに書いて渡します (`git commit -F <ファイル>`・`gh pr create --body-file <ファイル>`)。
- 文字列を探すときは、Bash ツールのコマンド `grep` ではなく、Grep ツールを使います。Grep ツールは、hook が検査するツールに入っていないためです。
- テストの固定データのディレクトリに、`runs` という名前を付けません。テストを実行するコマンド (節「テスト」) が拒否されないようにするためです。
