# 判定表に無い項目の調べ方

一覧の項目のうち、判定表にも記録にも無い項目 (判定の無い項目) を、Claude が調べて判定し、記録する手順。記録した判定は、次のトリアージから、調べ直さずに「Claude が <日付> に判定」として示す (計画 [docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md](../../../../docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md) の R20)。調べ直すのは、利用者が依頼したときだけ。

この文書で使う語:

- **判定**: 項目を消してよいかの判断。消してよい (`deletable`)・確認が要る (`review`)・残す (`keep`) の 3 つ。
- **判定表**: よく知られたディレクトリ (各ツールのキャッシュなど) の判定を書いた、プラグインが持つ表。
- **記録**: 利用者と Claude が決めた判定を、次回の判定に使うために保存したもの。様式は [files.md](../../../references/files.md) の節「`records.json`」にある。
- **入力のファイル**: Claude が Write ツールで書き、サブコマンドに引数 `--input-file` で渡す JSON のファイル。

## 調べる順

1. 項目のディレクトリの名前から、それを作ったアプリやツールを推測する。macOS のアプリは、名前がバンドル ID (`com.<会社>.<アプリ>` の形) のことが多い。
2. 項目の中身を読んで、推測を確認する。読むのは、ファイルとディレクトリの名前・大きいファイル・設定やデータベースのように見えるファイルの有無まで。中身は変えない。
3. そのアプリやツールの公式の文書 (無ければ、開発元が公開している説明) で、そのディレクトリの用途と、消してよいか、消し方を確認する。
4. 次の基準で判定を決める。確認できなかったことがあれば、「消してよい」にせず「確認が要る」にする。
   - 消してよい: キャッシュや一時ファイルだけで、消してもアプリやツールが作り直し、利用者のデータ・設定・ログインの情報が失われない。
   - 確認が要る: 利用者のデータ・設定・ログインの情報を含みうる、作り直しに長い時間や大きな通信が要る、用途を確認しきれない、のどれか。
   - 残す: 消すと、アプリやツールが動かなくなるか、利用者のデータが失われる。

## 根拠に残すもの

判定ごとに、根拠を 1 つ以上残す。根拠の無い判定は記録できない。

- 確認した文書の URL。
- 中身を読んで確認したこと (例: 「中に `*.cache` のファイルだけがある」「ファイル `Cookies` がある」)。

## 消すコマンド

判定が「残す」なら、消すコマンドは書かない (`null`)。それ以外は、次のどちらかにする。

- `{"type": "tool", "args": [...]}`: そのツールのキャッシュを消すコマンド。ツールが管理しているディレクトリは、ツールのコマンドで消す (計画の R15)。次の条件をすべて満たすときだけ書ける (計画の R16)。条件の詳細は [files.md](../../../references/files.md) の節「Claude の判定の入力」にある。
  - 許可した実行ファイルとサブコマンドの組 (ファイル `disk-usage-triage/scripts/disk_usage_triage/commands.py` の定数 `ALLOWED`) で始まる。組に無いツールは、`rm` にする。
  - 環境変数は、その組に許可した名前だけを付ける。
  - `docker`・`asdf`・`git` のコマンドではない。
  - シェルの特殊文字を含まない。
- `{"type": "rm"}`: ツールのコマンドが無いとき。削除のシェルスクリプトが、項目のディレクトリを `rm` で消す。

ツールのコマンドで、キャッシュの場所を引数か環境変数で指定できるときは、必ず指定する。項目のパスは、書き写さずに `{path}` (項目の絶対パス) と書き、名前は `{name}` と書く。利用者の設定でキャッシュの場所が変わっていると、場所を指定しないコマンドは、選んだ項目とは別の場所を消すため。パスを書き写すと、書き誤ったときに別の場所を消すため。

## アプリのプロセス名

項目が、起動中のアプリが使うキャッシュなら、そのアプリのプロセス名 (`pgrep -x` に渡す名前) を書く。削除のシェルスクリプトは、そのアプリが起動していれば、その項目を消さない (計画の R17・R39)。

## 記録する

調べた結果を、[files.md](../../../references/files.md) の節「Claude の判定の入力」の形で、入力のファイルに書く。入力には、項目のパスを書かない。項目は一覧の番号で指定する。入力を渡すサブコマンド `judge set` は、後の版 (計画の U6) で足す。

- 利用者の記録がある項目は、Claude の判定で置き換えられない。利用者が調べ直すよう依頼したときは、先に利用者に記録を消してもらう。
- 記録したことを、利用者に示す。
