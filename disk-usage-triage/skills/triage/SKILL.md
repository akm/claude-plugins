# disk-usage-triage:triage: 容量の大きい項目を調べて消す

このプラグインは作成中で、今の版 (0.4.0) のこのスキルは、設定を作る・変えることと、記録を見る・足す・消すことを行う。調査・一覧・削除のシェルスクリプトの作成は、後の版で足す。設定を確認し、設定が無ければ作り、変えるよう依頼されていれば変える。記録について依頼されていれば、節「記録を見る・消す」か節「「残す」と記録する」を行う。調査を依頼されていれば、調査はまだできないことを利用者に伝えて終了する。記録は、後の版で、一覧の項目の判定に使う。

この文書で使う語:

- **保存先のディレクトリ**: 設定・記録・トリアージのファイルを保存するディレクトリ `~/.claude/disk-usage-triage/`。ファイルの様式は [files.md](../../references/files.md) にある。
- **調べるディレクトリ**: `du -d 1` と同じ深さで調べるディレクトリ。利用者が指定したディレクトリだけを調べる。
- **プロジェクトのディレクトリ**: asdf の版の参照 (ファイル `.tool-versions` など) を探すディレクトリ。
- **入力のファイル**: Claude が Write ツールで書き、サブコマンドに引数 `--input-file` で渡す JSON のファイル。
- **記録**: 利用者と Claude が決めた判定 (消してよい・確認が要る・残す) を、次回の判定に使うために保存したもの。様式は [files.md](../../references/files.md) の節「`records.json`」にある。
- **対象**: 記録が指すもの。ディレクトリ・Docker の名前付きのボリューム・Compose のプロジェクト・image のリポジトリ・asdf のツールと版の組のどれか。

## スクリプトの実行

スクリプトは `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/disk_usage_triage.py" <サブコマンド>` で実行する (以下では `disk_usage_triage.py <サブコマンド>` と略す)。引数・出力の JSON・終了コードは、サブコマンドの `--help` で確認する。終了コードは、どのサブコマンドも次のとおりに扱う。

| 終了コード | 扱い |
| --- | --- |
| 0 | 続ける |
| 3 | 出力の `errors` を利用者に示し、どうするかを質問する。回答の無いまま進めない |
| 4 | 外部のコマンドが失敗した。出力を利用者に示して中断する |
| 1・2 | スクリプトの不具合。出力をそのまま利用者に示して中断する |

`--help` に、Bash ツールのバックグラウンドで実行すると書いてあるサブコマンドは、Bash ツールに引数 `run_in_background` を付けて実行し、完了の通知を受けてから出力を読む。調べるディレクトリごとの時間の上限の合計が、Bash ツールの時間の上限 (指定しなければ 120 秒、最大 600 秒) より長いことがあり、打ち切られると結果が出ないため。

## 設定を確認する

スキルを使うたびに、最初に `disk_usage_triage.py config show` を実行する。

- `exists` が `false` なら、節「設定を作る」に進む。
- 終了コード 3 で、`errors` が「Python 3.11 以上が必要」で始まるなら、コマンド `python3` が古い版を指している。`errors` (必要な版・実際の版・`python3` のパス) を利用者に示し、`python3` が 3.11 以上の版を指すようにするよう伝えて終了する。
- それ以外の終了コード 3 なら、`config.json` が壊れている。`errors` (壊れたファイルのパスと理由) を利用者に示し、利用者にファイルを直してもらう。Claude はファイルを直さない。直したと利用者が伝えたら、`config show` を実行し直す。
- 設定があれば、調べるディレクトリ (`scan_dirs`)・プロジェクトのディレクトリ (`project_dirs`)・時間の上限 (`timeout_seconds` 秒) を利用者に示す。

## 設定を作る

設定が無いときに行う。

1. 利用者に、調べるディレクトリとプロジェクトのディレクトリを質問する。Claude が決めて保存しない。候補を示すときは、候補であって、利用者が選んだものだけを保存することを伝える。
   - 調べるディレクトリ: 例は `~/Library/Caches`・`~/.asdf`・`~/Library/Containers`・`~/Library/Developer`。1 つ以上。一方を他方の下にしない (`~/Library` と `~/Library/Caches` を両方書かない)。
   - プロジェクトのディレクトリ: 作業するリポジトリがあるディレクトリ (例: `~/workspace`)。1 つ以上。ここにも `~/.tool-versions` にも参照が無い asdf の版は、参照されていない版として「消してよい」と判定されることを伝える。
   - どちらも、絶対パスか、`~` か `~/` で始まるパスで書く。相対パスは受け付けない。
   - 時間の上限は質問しない。利用者が指定したときだけ、`timeout_seconds` に書く。省くと 300 秒になる。
2. Write ツールで、`config show` の出力の `inputs_dir` の下のファイル `config-set.json` に、回答を JSON で書く。様式は [files.md](../../references/files.md) の節「`config set` の入力」にある。パスは、利用者が書いたとおりに書く (`~` を展開しない)。
3. `disk_usage_triage.py config set --input-file <書いたファイルの絶対パス>` を実行する。終了コード 3 なら、`errors` を利用者に示し、直した回答を質問して、手順 2 からやり直す。
4. 保存した設定 (出力の `config`) を利用者に示す。

## 設定を変える

利用者が設定を変えるよう依頼したときに行う。

1. `disk_usage_triage.py config show` を実行し、今の設定 (出力の `config`) を読む。
2. 利用者の依頼に従って、変えた後の設定の全体を作る。`config set` は、入力の内容で設定の全体を置き換えるので、変えないキーも今の値のまま書く。`timeout_seconds` を書かないと、今の値ではなく 300 秒になる。
3. 今の設定と変えた後の設定を利用者に示し、変えてよいかを確認する。回答の無いまま進めない。
4. 節「設定を作る」の手順 2・3 と同じく、入力のファイルに書いて `config set` を実行する。
5. 出力の `previous` (変える前の設定) と `config` (変えた後の設定) を利用者に示す。

## 記録を見る・消す

利用者が、記録を見るよう依頼したときと、記録を消すよう依頼したときに行う。

1. `disk_usage_triage.py records list` を実行する。終了コード 3 なら、`records.json` が壊れている。`errors` (壊れたファイルのパスと理由) を利用者に示し、利用者にファイルを直してもらう。Claude はファイルを直さない。
2. 記録 (出力の `records`) を表で示す。列は、番号 (`number`)・対象 (`display`)・判定 (消してよい・確認が要る・残す)・だれが決めたか (利用者・Claude)・日付 (`decided_on`)・理由 (`reason`。`null` なら空欄)。記録が無ければ、無いことを伝える。
3. 消すよう依頼されていて、どの記録を消すかが番号で決まっていなければ、表を示して番号を質問する。回答の無いまま進めない。
4. `disk_usage_triage.py records remove --listing <手順 1 の出力の listing> <番号>...` を実行する。
   - 終了コード 3 で、一覧を示した後に記録が変わったという誤りなら、手順 1 からやり直し、新しい表で番号を利用者に確認する。
   - それ以外の終了コード 3 なら、`errors` を利用者に示し、どうするかを質問する。
5. 消した記録 (出力の `removed`) を利用者に示す。

## 「残す」と記録する

利用者が会話で、ある対象を残すと言ったときに行う (例: 「`~/Library/Caches/com.example.app` は残す」「Docker のボリューム `mysql-data` は消さない」)。記録したことは、必ず利用者に示す。

1. 対象を決める。対象の種類と書き方は、[files.md](../../references/files.md) の節「対象」にある。ディレクトリのパスは、利用者が書いたとおりに書く (`~` を展開しない)。Docker と asdf の名前も、利用者が言ったとおりに書き、Claude が推測で補わない。どの種類の対象かが決まらないときは、利用者に質問する。
2. Write ツールで、`config show` の出力の `inputs_dir` の下のファイル `records-add.json` に、入力を JSON で書く。様式は [files.md](../../references/files.md) の節「`records add` の入力」にある。`judgment` は `keep` にする。利用者が残す理由を言ったときだけ、`reason` にその理由を書く。
3. `disk_usage_triage.py records add --input-file <書いたファイルの絶対パス>` を実行する。終了コード 3 なら、`errors` を利用者に示す。
   - 保護の一覧の場所なので記録しないという誤りなら、記録しなくても常に「残す」と判定することを伝えて終える。
   - 設定が無いという誤りなら、節「設定を作る」を行ってから、手順 3 をやり直す。
   - それ以外なら、直した回答を質問して、手順 1 からやり直す。
4. 記録した対象 (出力の `display`) と理由を利用者に示す。出力の `previous` が `null` でなければ、前の記録 (判定・だれが決めたか・日付) を置き換えたことも示す。
