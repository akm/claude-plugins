# disk-usage-triage:triage: 容量の大きい項目を調べて消す

このプラグインは作成中で、今の版 (0.5.0) のこのスキルは、設定を作る・変えること、調べるディレクトリを調べて一覧を示すこと、消す項目を選ぶこと、判定を記録することを行う。削除のシェルスクリプトの作成・削除の後の比較・asdf と Docker とアプリの worktree の一覧は、後の版で足す。設定を確認し、設定が無ければ作り、変えるよう依頼されていれば変える。調べるよう依頼されていれば、節「調べる」を行う。記録について依頼されていれば、節「記録を見る・消す」か節「「残す」と記録する」を行う。選んだ項目を消すよう依頼されたら、削除のシェルスクリプトはまだ作れないことを利用者に伝える。

この文書で使う語:

- **保存先のディレクトリ**: 設定・記録・トリアージのファイルを保存するディレクトリ `~/.claude/disk-usage-triage/`。ファイルの様式は [files.md](../../references/files.md) にある。
- **調べるディレクトリ**: `du -d 1` と同じ深さで調べるディレクトリ。利用者が指定したディレクトリだけを調べる。
- **プロジェクトのディレクトリ**: asdf の版の参照 (ファイル `.tool-versions` など) を探すディレクトリ。
- **入力のファイル**: Claude が Write ツールで書き、サブコマンドに引数 `--input-file` で渡す JSON のファイル。
- **記録**: 利用者と Claude が決めた判定 (消してよい・確認が要る・残す) を、次回の判定に使うために保存したもの。様式は [files.md](../../references/files.md) の節「`records.json`」にある。
- **対象**: 記録が指すもの。ディレクトリ・Docker の名前付きのボリューム・Compose のプロジェクト・image のリポジトリ・asdf のツールと版の組のどれか。
- **トリアージ**: 調べ始めてから、削除の後の比較までの 1 回分の作業。サブコマンド `run start` で始め、出力のトリアージの ID (例: `20261128-153012`) を、ほかのサブコマンドの引数 `--run` に渡す。
- **一覧**: 調べたディレクトリの 1 つ下の階層の項目を、使用量の多い順に並べ、英字 (`A`・`B` …) と番号 (`A1`・`A2` …) を付けたもの。最初の一覧 (`A`) は調べるディレクトリの項目をまとめたもの。一覧の項目を指定すると、その下の階層を次の英字の一覧にする。前に示した一覧の項目も、番号で指定できる。
- **判定**: 項目を消してよいかの判断。消してよい・確認が要る・残す の 3 つ。保護の一覧・記録・判定表のどれでも決まらない項目は「判定なし」で、Claude が調べて判定する。
- **選んだ項目**: 利用者が消すと選んだ項目。1 つのトリアージで、複数の一覧にまたがって 1 つにまとめる。

## スクリプトの実行

スクリプトは `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/disk_usage_triage.py" <サブコマンド>` で実行する (以下では `disk_usage_triage.py <サブコマンド>` と略す)。引数・出力の JSON・終了コードは、サブコマンドの `--help` で確認する。終了コードは、どのサブコマンドも次のとおりに扱う。

| 終了コード | 扱い |
| --- | --- |
| 0 | 続ける |
| 3 | 出力の `errors` を利用者に示し、どうするかを質問する。回答の無いまま進めない |
| 4 | 外部のコマンドが失敗した。出力を利用者に示して中断する |
| 1・2 | スクリプトの不具合。出力をそのまま利用者に示して中断する |

`--help` に、Bash ツールのバックグラウンドで実行すると書いてあるサブコマンドは、Bash ツールに引数 `run_in_background` を付けて実行し、完了の通知を受けてから出力を読む。調べるディレクトリごとの時間の上限の合計が、Bash ツールの時間の上限 (指定しなければ 120 秒、最大 600 秒) より長いことがあり、打ち切られると結果が出ないため。

## 設定を確認する

スキルを使うたびに、最初に `disk_usage_triage.py config show` を実行する。

- `exists` が `false` なら、節「設定を作る」に進む。
- 終了コード 3 で、`errors` が「Python 3.11 以上が必要」で始まるなら、コマンド `python3` が古い版を指している。`errors` (必要な版・実際の版・`python3` のパス) を利用者に示し、`python3` が 3.11 以上の版を指すようにするよう伝えて終了する。
- それ以外の終了コード 3 なら、`config.json` が壊れている。`errors` (壊れたファイルのパスと理由) を利用者に示し、利用者にファイルを直してもらう。Claude はファイルを直さない。直したと利用者が伝えたら、`config show` を実行し直す。
- 設定があれば、調べるディレクトリ (`scan_dirs`)・プロジェクトのディレクトリ (`project_dirs`)・時間の上限 (`timeout_seconds` 秒) を利用者に示す。

## 設定を作る

設定が無いときに行う。

1. 利用者に、調べるディレクトリとプロジェクトのディレクトリを質問する。Claude が決めて保存しない。候補を示すときは、候補であって、利用者が選んだものだけを保存することを伝える。
   - 調べるディレクトリ: 例は `~/Library/Caches`・`~/.asdf`・`~/Library/Containers`・`~/Library/Developer`。1 つ以上。一方を他方の下にしない (`~/Library` と `~/Library/Caches` を両方書かない)。
   - プロジェクトのディレクトリ: 作業するリポジトリがあるディレクトリ (例: `~/workspace`)。1 つ以上。ここにも `~/.tool-versions` にも参照が無い asdf の版は、参照されていない版として「消してよい」と判定されることを伝える。
   - どちらも、絶対パスか、`~` か `~/` で始まるパスで書く。相対パスは受け付けない。
   - 時間の上限は質問しない。利用者が指定したときだけ、`timeout_seconds` に書く。省くと 300 秒になる。
2. Write ツールで、`config show` の出力の `inputs_dir` の下のファイル `config-set.json` に、回答を JSON で書く。様式は [files.md](../../references/files.md) の節「`config set` の入力」にある。パスは、利用者が書いたとおりに書く (`~` を展開しない)。
3. `disk_usage_triage.py config set --input-file <書いたファイルの絶対パス>` を実行する。終了コード 3 なら、`errors` を利用者に示し、直した回答を質問して、手順 2 からやり直す。
4. 保存した設定 (出力の `config`) を利用者に示す。

## 設定を変える

利用者が設定を変えるよう依頼したときに行う。

1. `disk_usage_triage.py config show` を実行し、今の設定 (出力の `config`) を読む。
2. 利用者の依頼に従って、変えた後の設定の全体を作る。`config set` は、入力の内容で設定の全体を置き換えるので、変えないキーも今の値のまま書く。`timeout_seconds` を書かないと、今の値ではなく 300 秒になる。
3. 今の設定と変えた後の設定を利用者に示し、変えてよいかを確認する。回答の無いまま進めない。
4. 節「設定を作る」の手順 2・3 と同じく、入力のファイルに書いて `config set` を実行する。
5. 出力の `previous` (変える前の設定) と `config` (変えた後の設定) を利用者に示す。

## 調べる

利用者が、ディスクの空きを作りたい・容量の大きいディレクトリを調べたいと依頼したときに行う。

1. 節「設定を確認する」を行う。設定が無ければ、節「設定を作る」を行ってから続ける。
2. `disk_usage_triage.py run start` を実行し、出力のトリアージの ID (`run`) を、このトリアージのあいだ使う。
3. `disk_usage_triage.py scan --run <ID>` を、Bash ツールのバックグラウンドで実行する (`--help` に書いてあるため)。完了の通知を受けてから出力を読む。終了コード 3 なら、`errors` を利用者に示す。
4. 節「一覧を示す」を行う。
5. 利用者の依頼に応じて、次のどれかを行う。
   - 項目の下を見たい (例: 「A3 の下を見せて」): 節「下の階層を一覧にする」
   - 項目を選ぶ・選ぶのをやめる・選んだ項目を見る: 節「項目を選ぶ」
   - 項目を残す (例: 「A7 は残す」): 節「「残す」と記録する」
   - 判定の無い項目を調べる: 節「判定の無い項目を調べる」
   - 項目の消したときの影響と消すコマンドを知りたい: 一覧の出力の項目 (`items`) の `impact` と `command_text` を示す
   - その他の行の項目も見たい: `disk_usage_triage.py list show --run <ID> <英字> --all` を実行し、節「一覧を示す」と同じく示す
   - 読めなかったパスを知りたい: `disk_usage_triage.py list show --run <ID> <英字> --unreadable` を実行し、出力の `unreadable` を示す
   - 前に示した一覧をもう一度見たい: `disk_usage_triage.py list show --run <ID> <英字>` を実行し、節「一覧を示す」と同じく示す。判定は、示すたびに、その時の記録と判定表から求め直す
   - 選んだ項目を消したい: 削除のシェルスクリプトを作る機能はまだ無いことを伝える

番号は、利用者が書いた番号を、英字を大文字にして渡す (`a3` は `A3`)。

## 一覧を示す

`scan` と `list show` の出力を、次のとおり示す。

1. 出力の `table` (Markdown の表) を、そのまま示す。列は、番号・パス・使用量・判定・理由。表を作り直したり、行を並べ替えたりしない。
2. 出力の `notes` (注記) を、表の下に箇条書きで、そのまま示す。注記には、調べたディレクトリごとの使用量、項目に入らない使用量 (直下のファイルなど)、結果を出せなかったディレクトリ、読めなかったディレクトリを含む項目、「消してよい」の項目をまとめて選ぶ選び方がある。
3. 表に示した項目 (`items`) に、判定の無い項目 (`judgment` が `null`) があれば、その数を伝え、すべて調べるか、どれを調べるかを質問する。回答の無いまま調べない。判定の無い項目は、調べて判定を記録するまで選べないことも伝える。

## 下の階層を一覧にする

1. `disk_usage_triage.py scan --run <ID> --item <番号>` を、Bash ツールのバックグラウンドで実行し、完了の通知を受けてから出力を読む。同じ項目をもう一度調べると、測り直して新しい一覧を作る。
2. 出力の `dedicated_list` が `null` でなければ (asdf の版・Docker・アプリの worktree の項目)、その一覧は後の版で足すことを伝える。
3. 終了コード 3 なら、`errors` を利用者に示す。一覧が 26 個 (`A`〜`Z`) に達したという誤りなら、新しいトリアージ (`run start`) を始めると、選んだ項目は空から始まることも伝える。
4. それ以外は、節「一覧を示す」を行う。

## 項目を選ぶ

利用者が、消す項目を番号で選んだとき (例: 「A1 と A5 を消したい」) に行う。

1. `disk_usage_triage.py select add --run <ID> <番号>...` を、Bash ツールのバックグラウンドで実行し、完了の通知を受けてから出力を読む。
   - 利用者が、ある一覧の「消してよい」をすべて選ぶよう依頼したときだけ、番号の代わりに `--all-deletable <英字>` を付ける。表に示した項目だけを選ぶ。その他の行の項目も選ぶよう依頼されたときだけ、`--all` も付ける。
2. 出力を、次のとおり示す。
   - `added` (選んだ項目): 番号・パス (`display`)・使用量 (`size`) と、消したときの影響 (`impact`) と消すコマンド (`command_text`)。
   - `replaced`: 親を選んだので、選んだ項目から外した子。
   - `already`: 既に選んでいた項目。
   - `rejected` (選ばなかった項目): 番号と理由 (`reasons`)。判定の無い項目なら、調べるかを質問する。保護の一覧の場所や「残す」の項目を含む項目なら、下の階層を一覧にして、選べる項目を選ぶよう伝える。
   - `others_deletable` が `null` でなく、`count` が 1 以上なら、その他の行に「消してよい」の項目が残っていることと、その数と合計 (`size`) を伝える。
   - `selection` (選んだ項目の全体): 数と合計の使用量。
3. 利用者が選ぶのをやめると言ったときは、`disk_usage_triage.py select remove --run <ID> <番号>...` を実行し、外した項目 (`removed`)・選んでいなかった項目 (`not_selected`)・選んだ項目の全体 (`selection`) を示す。
4. 利用者が選んだ項目を見たいと言ったときは、`disk_usage_triage.py select show --run <ID>` を実行し、出力の `table` と、選んだ項目の全体 (`selection`) を示す。

## 判定の無い項目を調べる

節「一覧を示す」の手順 3 で、利用者が調べると回答した項目について行う。利用者が依頼したときは、Claude が前に判定した項目も調べ直す。

1. [research.md](references/research.md) の手順で調べる。
2. Write ツールで、`config show` の出力の `inputs_dir` の下のファイル `judge-set.json` に、調べた結果を JSON で書く。様式は [files.md](../../references/files.md) の節「Claude の判定の入力」にある。項目のパスは書かない。
3. `disk_usage_triage.py judge set --run <ID> <番号> --input-file <書いたファイルの絶対パス>` を実行する。
   - 終了コード 3 で、判定表・利用者の記録・親のディレクトリの記録・保護の一覧で判定が決まっているという誤りなら、Claude の判定は記録しないことを伝える。利用者の記録を調べ直すよう依頼されていたなら、先に利用者に記録を消してもらう (節「記録を見る・消す」)。
   - 入力の誤りなら、直して手順 2 からやり直す。
4. 記録した判定 (出力の `item` の `judgment_label` と `reason`) を利用者に示す。調べた項目をすべて記録したら、`list show` で一覧をもう一度示す。

## 記録を見る・消す

利用者が、記録を見るよう依頼したときと、記録を消すよう依頼したときに行う。

1. `disk_usage_triage.py records list` を実行する。終了コード 3 なら、`records.json` が壊れている。`errors` (壊れたファイルのパスと理由) を利用者に示し、利用者にファイルを直してもらう。Claude はファイルを直さない。
2. 記録 (出力の `records`) を表で示す。列は、番号 (`number`)・対象 (`display`)・判定 (消してよい・確認が要る・残す)・だれが決めたか (利用者・Claude)・日付 (`decided_on`)・理由 (`reason`。`null` なら空欄)。記録が無ければ、無いことを伝える。
3. 消すよう依頼されていて、どの記録を消すかが番号で決まっていなければ、表を示して番号を質問する。回答の無いまま進めない。
4. `disk_usage_triage.py records remove --listing <手順 1 の出力の listing> <番号>...` を実行する。
   - 終了コード 3 で、一覧を示した後に記録が変わったという誤りなら、手順 1 からやり直し、新しい表で番号を利用者に確認する。
   - それ以外の終了コード 3 なら、`errors` を利用者に示し、どうするかを質問する。
5. 消した記録 (出力の `removed`) を利用者に示す。

## 「残す」と記録する

利用者が会話で、ある対象を残すと言ったときに行う (例: 「`~/Library/Caches/com.example.app` は残す」「Docker のボリューム `mysql-data` は消さない」)。記録したことは、必ず利用者に示す。

1. 対象を決める。
   - 一覧の項目 (例: 「A7 は残す」) なら、番号で指定する。項目のパスを入力に書かない。
   - それ以外は、対象の種類と書き方を [files.md](../../references/files.md) の節「対象」で確認する。ディレクトリのパスは、利用者が書いたとおりに書く (`~` を展開しない)。Docker と asdf の名前も、利用者が言ったとおりに書き、Claude が推測で補わない。どの種類の対象かが決まらないときは、利用者に質問する。
2. Write ツールで、`config show` の出力の `inputs_dir` の下のファイル `records-add.json` に、入力を JSON で書く。様式は [files.md](../../references/files.md) の節「`records add` の入力」にある。`judgment` は `keep` にする。利用者が残す理由を言ったときだけ、`reason` にその理由を書く。一覧の項目なら、`target` を書かない。
3. `disk_usage_triage.py records add --input-file <書いたファイルの絶対パス>` を実行する。一覧の項目なら、`--run <ID> --item <番号>` も付ける。終了コード 3 なら、`errors` を利用者に示す。
   - 保護の一覧の場所なので記録しないという誤りなら、記録しなくても常に「残す」と判定することを伝えて終える。
   - 設定が無いという誤りなら、節「設定を作る」を行ってから、手順 3 をやり直す。
   - それ以外なら、直した回答を質問して、手順 1 からやり直す。
4. 記録した対象 (出力の `display`) と理由を利用者に示す。出力の `previous` が `null` でなければ、前の記録 (判定・だれが決めたか・日付) を置き換えたことも示す。
