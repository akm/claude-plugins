# 保存先のディレクトリのファイルの様式

disk-usage-triage のスクリプトが読み書きするファイルの様式。設計は、計画 [docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md](../../docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md) の KTD2・KTD3 にある。

この文書は、計画の U2 と U4 で使うファイル (設定・記録と、Claude が書く入力のファイル) を書いている。トリアージのファイルは、それを使う単位で足す。

## 保存先のディレクトリ

保存先のディレクトリは、設定・記録・トリアージのファイルを保存するディレクトリ `~/.claude/disk-usage-triage/` (計画の R3)。テストでは、環境変数 `DISK_USAGE_TRIAGE_HOME` で場所を変える。

| ファイル | 中身 |
| --- | --- |
| `config.json` | 設定 (調べるディレクトリ・プロジェクトのディレクトリ・時間の上限) |
| `records.json` | 記録 (利用者と Claude が決めた判定) |
| `lock` | 書き込みを順にするためのロックのファイル (中身は空) |
| `inputs/` | Claude が Write ツールで書き、サブコマンドに引数 `--input-file` で渡す入力のファイルのディレクトリ |

- 中身はこのマシンのパスを指すので、保存先のディレクトリを、ほかのマシンと同期・共有しない (計画の KTD2)。
- スクリプトが保存する JSON のファイルは UTF-8 で、キー `version` (今は `1`) を持つ。
- スクリプトの書き込みは、ファイル `lock` の排他ロック (`fcntl.flock`) を取ってから行う。同じディレクトリの一時ファイルに書いてから名前を変える (`os.replace`) ので、書き込みの途中で失敗しても、元のファイルが残る。
- 入力のファイル (`inputs/` の下) には、上の `version` と書き込みの規則は当てはまらない。様式は節「入力のファイル (`inputs/`)」にある。
- 壊れたファイル (JSON として読めない・オブジェクトでない・`version` が `1` でない・キーや値の形が違う) を、空のファイルとして扱わない。`config.json` が壊れていると、設定を読むサブコマンドも書くサブコマンドも、何も書かずに終了コード 3 で、壊れたファイルのパスと理由を示す。`records.json` も同じく、壊れていると、記録を読むサブコマンド (`records list`・`records add`・`records remove`) は何も書かずに終了コード 3 で示す。壊れた記録を空として扱うと、利用者が「残す」と記録した項目が、記録の無いときの判定で示されるため (計画の KTD2)。利用者がファイルを直してから、実行し直す。

## `config.json`

設定。サブコマンド `config set` だけが書く。

```json
{
  "version": 1,
  "scan_dirs": ["~/Library/Caches", "~/.asdf", "~/Library/Containers"],
  "project_dirs": ["~/workspace"],
  "timeout_seconds": 300
}
```

| キー | 値 |
| --- | --- |
| `version` | `1` |
| `scan_dirs` | 調べるディレクトリ (`du -d 1` と同じ深さで調べるディレクトリ。計画の R1) の配列。1 つ以上 |
| `project_dirs` | プロジェクトのディレクトリ (asdf の版の参照を探すディレクトリ。計画の R2) の配列。1 つ以上 |
| `timeout_seconds` | 調べるディレクトリごとの時間の上限 (秒。計画の R4)。1 以上 86,400 (1 日) 以下の整数。Docker の調査と、asdf の版の参照の探索にも同じ上限を使う |

パスは、次のように書く。

- 絶対パスか、`~` か `~/` で始まるパスにする。相対パスと、`~<利用者名>/` で始まるパス (ほかの利用者のホームディレクトリを指す書き方) は受け付けない (計画の KTD3)。
- 書いたとおりに保存する。`~` を展開せず、末尾の `/` や途中の `..` も直さない。`~` は、使うときに利用者のホームディレクトリ (環境変数 `HOME`) にする。

`config.json` が壊れているかは、上の形だけで判定する。保存した後でディレクトリが無くなっても、壊れているとはしない。

## `records.json`

記録。利用者と Claude が決めた判定を、次回の判定に使うために保存したもの (計画の R18〜R22・KTD16)。サブコマンド `records add`・`records remove` と、後の版で足すサブコマンド `judge set` (Claude の判定。計画の U6)・`script create` (利用者が消すと選んだディレクトリ。計画の U7) が書く。

```json
{
  "version": 1,
  "records": [
    {
      "target": {"kind": "directory", "path": "/Users/u/Library/Caches/com.example.app"},
      "judgment": "review",
      "decided_by": "claude",
      "decided_on": "2026-11-27",
      "reason": "アプリ Example のキャッシュで、ログインの情報も含む",
      "impact": "次にアプリを起動したときに、ログインし直す",
      "basis": ["https://example.com/docs/cache", "中にファイル Cookies があることを確認した"],
      "command": {"type": "rm"},
      "process_names": ["Example"]
    },
    {
      "target": {"kind": "docker-volume", "name": "mysql-data"},
      "judgment": "keep",
      "decided_by": "user",
      "decided_on": "2026-11-27",
      "reason": "開発に使うデータベースのデータ",
      "impact": null,
      "basis": [],
      "command": null,
      "process_names": []
    }
  ]
}
```

| キー | 値 |
| --- | --- |
| `version` | `1` |
| `records` | 記録の配列。記録のキーは、下の表 |

記録のキー:

| キー | 値 |
| --- | --- |
| `target` | 記録が指すもの (対象)。節「対象」の形 |
| `judgment` | 判定。消してよい `deletable`・確認が要る `review`・残す `keep` のどれか。利用者の記録は `deletable` か `keep` |
| `decided_by` | だれが決めたか。利用者 `user` か Claude `claude` |
| `decided_on` | 記録した日 (`YYYY-MM-DD`)。スクリプトが手元の日付を書く |
| `reason` | 判定の理由 (1 文)。空でない文字列か `null`。Claude の記録では必須 |
| `impact` | 消したときの影響。空でない文字列か `null`。Claude の記録では必須 |
| `basis` | 根拠 (調べた URL か、確認したこと) の、空でない文字列の配列。Claude の記録では 1 つ以上 |
| `command` | Claude が書いた消すコマンド (節「Claude の判定の入力」の形)。無ければ `null` |
| `process_names` | そのディレクトリを使うアプリのプロセス名 (`pgrep -x` に渡す名前) の配列。名前は `/` を含まない、空でない文字列 |

### 対象

| `kind` | ほかのキー | 対象 |
| --- | --- | --- |
| `directory` | `path` | ディレクトリ。`path` は、シンボリックリンクを解決した絶対パス |
| `docker-volume` | `name` | Docker の名前付きのボリューム |
| `docker-compose-project` | `name` | Compose のプロジェクト (ボリュームのラベル `com.docker.compose.project` の値) |
| `docker-image-repository` | `name` | image のリポジトリ |
| `asdf-version` | `tool`・`version` | asdf のツールと版の組。`version` は、ディレクトリ `installs/<ツール>/` の下の、版のディレクトリの名前 |

Docker と asdf の対象は、名前の形だけを検査する。ボリュームや版があるかは確認しない (計画の R18)。

| 名前 | 形 |
| --- | --- |
| ボリュームの名前 | Docker の規則 `[a-zA-Z0-9][a-zA-Z0-9_.-]+` に合う |
| Compose のプロジェクトの名前 | Compose の規則 `[a-z0-9][a-z0-9_-]*` に合う |
| image のリポジトリの名前 | 空でない。空白と制御文字・タグ (最後の `/` より後の `:`)・`@` を含まない |
| asdf のツールと版 | 空でない。`/` と制御文字を含まない。`.` と `..` ではない |

### 記録の規則

- 対象 1 つに、記録は 1 つ。同じ対象を記録し直すと置き換える (計画の R18)。ディレクトリは、パスの文字列か、ディレクトリの識別子 (デバイス番号と inode 番号。比べるときに求める) が同じなら、同じ対象とする (計画の KTD16)。ただし、記録のパスが、シンボリックリンクを解決すると別のパスになるとき (記録したディレクトリか、その親が、後でシンボリックリンクに置き換わったとき) は、識別子では比べない。パスの文字列で一致する記録と、識別子で一致する記録が別々にあれば、パスの文字列で一致する記録を同じ対象とする。
- 保護の一覧の場所には、どの判定も記録しない (計画の R18)。
- Claude の記録は、ディレクトリの対象だけ。判定が `keep` なら `command` は `null`。
- 利用者の記録が既にある記録を置き換えるときは、判定・だれが決めたか・日付だけを変え、ほかのキーを残す。利用者が理由を言ったときだけ、`reason` をその理由にする (計画の R21)。
- Claude の記録で、利用者の記録を置き換えない。Claude が調べ直すときは、利用者が先に記録を消す (計画の R20)。
- 利用者の「消してよい」は、ディレクトリの対象だけ。削除のシェルスクリプトを作るときに記録する (計画の R21)。
- Docker と asdf の対象の記録は、`command` が `null`、`process_names` が空の配列。

`records.json` が壊れているかは、上の形と、同じ対象 (キーの値が同じ) の記録が 2 つ以上あるかで判定する。Claude が書いたコマンドが、今の版の検査 (節「Claude の判定の入力」) に合わないことは、壊れているとしない。検査は、削除のシェルスクリプトを作るときにもう一度行う (計画の R20)。

## 入力のファイル (`inputs/`)

Claude は、サブコマンドに渡す JSON を、Write ツールで `inputs/` の下のファイルに書き、そのパスを引数 `--input-file` で渡す (計画の KTD3)。トリアージのディレクトリ (`runs/<ID>/`) の下には書かない。hook (ファイル `disk-usage-triage/hooks/hooks.json`) が、`runs` のパスを含むコマンドと、`runs` の下のファイルへの書き込みを拒否するため (計画の KTD8・KTD9)。

- 知らないキーは誤りにし、値を検査する。誤りがあれば何も保存せず、終了コード 3 で返し、出力の `errors` に理由をすべて書く。
- スクリプトが求められる値 (パスを展開した値・使用量など) は受け取らない。

### `config set` の入力

`config.json` から `version` を除いたもの。`config set` は、この内容で設定の全体を置き換える (書いたキーだけを変えることはしない)。`timeout_seconds` は省くと 300 になり、前の設定の値は残らない。`version` は書かない (書くと、知らないキーとして誤りにする)。

```json
{
  "scan_dirs": ["~/Library/Caches", "~/.asdf"],
  "project_dirs": ["~/workspace"]
}
```

次の検査に合わないと、誤りにする。

- `scan_dirs` と `project_dirs` は、1 つ以上の要素を持つ配列。
- 各パスは、節「`config.json`」のパスの書き方に従い、`~` を展開した場所にディレクトリがある (シンボリックリンクはたどる)。
- `scan_dirs` では、同じディレクトリを 2 回書かず、一方を他方の下にしない (例: `~/Library` と `~/Library/Caches`)。同じディレクトリかは、パスの文字列ではなくディレクトリの識別子 (デバイス番号と inode 番号) で比べるので、シンボリックリンクと、大文字小文字を区別しないファイルシステム (macOS の標準) で大文字小文字だけが違う書き方も、同じディレクトリとして扱う。同じ項目を一覧に 2 回出したり、合計に 2 回数えたりしないため。`project_dirs` では比べない。
- `timeout_seconds` は 1 以上 86,400 (1 日) 以下の整数 (上限の理由は計画の R4)。

### `records add` の入力

利用者が会話で「残す」と言ったときに、Claude が書く (計画の R21)。

```json
{
  "target": {"kind": "directory", "path": "~/Library/Caches/com.example.app"},
  "judgment": "keep",
  "reason": "アプリの設定を含む"
}
```

| キー | 値 |
| --- | --- |
| `target` | 対象 (節「対象」の形)。必須 |
| `judgment` | `keep` だけ。必須。利用者の「消してよい」は、削除のシェルスクリプトを作るときに記録する |
| `reason` | 利用者が言った理由。空でない文字列。省ける |

- ディレクトリの `path` は、節「`config.json`」のパスの書き方 (絶対パスか、`~` か `~/` で始まるパス) で書き、ディレクトリがあること (シンボリックリンクはたどる) を確認する。スクリプトが、シンボリックリンクを解決した絶対パスにして記録する。
- ディレクトリの記録には、設定 (`config.json`) が要る。調べるディレクトリが、保護の一覧に入るため。

### Claude の判定の入力

判定表に無い項目を Claude が調べて判定したときに、Claude が書く (計画の R20)。この入力を受け取るサブコマンド `judge set` は、後の版 (計画の U6) で足す。対象は一覧の番号で指定し、入力には書かない。調べ方は、スキル `triage` の文書 [research.md](../skills/triage/references/research.md) にある。

```json
{
  "judgment": "review",
  "reason": "アプリ Example のキャッシュで、ログインの情報も含む",
  "impact": "次にアプリを起動したときに、ログインし直す",
  "basis": ["https://example.com/docs/cache", "中にファイル Cookies があることを確認した"],
  "command": {"type": "tool", "args": ["uv", "cache", "prune", "--cache-dir", "{path}"]},
  "process_names": ["Example"]
}
```

| キー | 値 |
| --- | --- |
| `judgment` | 判定。`deletable`・`review`・`keep` のどれか。必須 |
| `reason` | 判定の理由 (1 文)。空でない文字列。必須 |
| `impact` | 消したときの影響。空でない文字列。必須 (`keep` でも、消すと何が起きるかを書く) |
| `basis` | 根拠 (調べた URL か、確認したこと) の、空でない文字列の配列。1 つ以上。必須 |
| `command` | 消すコマンド。`judgment` が `keep` なら `null`、それ以外は `{"type": "rm"}` か `{"type": "tool", "args": [...], "env": {...}}`。必須 |
| `process_names` | そのディレクトリを使うアプリのプロセス名の配列。省ける (省略は空の配列と同じ) |

`{"type": "tool"}` のコマンドは、次の検査に合わないと誤りにする (計画の R16・KTD6)。

- `args` は、1 つ以上の要素を持つ配列。先頭は、許可した実行ファイルとサブコマンドの組 (ファイル `disk-usage-triage/scripts/disk_usage_triage/commands.py` の定数 `ALLOWED`) で始まる。
- 実行ファイル (`args` の先頭) を、パス (`/` を含む名前) で書かない。`docker`・`asdf`・`git` のコマンドは書かない。これらは、それぞれの一覧でスクリプトが組み立てる。
- `env` は省ける。環境変数の名前は、その組に許可した名前 (定数 `ALLOWED` の `env`) だけ。
- 引数と環境変数の値は、空でない文字列で、NUL 文字と、シェルの特殊文字 (`;`・`|`・`&`・`$`・バッククォート・`<`・`>`・改行) を含まない。空白は含んでよい。
- 引数と環境変数の値には、`{path}` (対象のディレクトリの絶対パス) と `{name}` (その名前) を書ける。要素の一部には書けず、要素全体をこの文字列にする。`{` と `}` は、この 2 つの文字列にだけ書ける。
- パスの形の値 (`/`・`~`・`.` で始まる値と、`/` を含む値) は書けない。項目の場所は `{path}` で指定する。項目の外のパスを書いた値で、選んだ項目の外を消させないため。
