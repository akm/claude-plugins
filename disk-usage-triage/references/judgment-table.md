# 判定表の様式

disk-usage-triage の判定表 (ファイル `disk-usage-triage/scripts/disk_usage_triage/judgment-table.json`) の様式。この文書が、判定表の様式の SSOT。判定表を読むのは、モジュール `judge` (ファイル `disk-usage-triage/scripts/disk_usage_triage/judge.py`)。設計は、計画 [docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md](../../docs/plans/2026-11-22-1630-feat-disk-usage-triage-plan.md) の KTD5・KTD6 にある。

この文書で使う語:

- **項目**: 一覧の 1 行が表すもの。ディレクトリ・asdf の版・Docker のボリュームなど。
- **判定**: 項目を消してよいかの判断。消してよい (`deletable`)・確認が要る (`review`)・残す (`keep`) の 3 つ。
- **判定表**: よく知られたディレクトリ (各ツールのキャッシュなど) について、判定・理由・消したときの影響・消すコマンドを書いた、プラグインが持つ表。
- **保護の一覧**: 消す対象に選べない場所の一覧。判定表とは別に、モジュール `judge` のコードに持つ (節「判定表に書かないもの」)。
- **専用の一覧**: ディレクトリの一覧とは別に作る、asdf の版の一覧・Docker の一覧と、アプリの worktree の案内。

## 行

判定表は、行 (JSON のオブジェクト) の配列。行のキーは次のとおり。表に無いキーは誤りにする。

| キー | 値 |
| --- | --- |
| `pattern` | 行を使うディレクトリのパターン (節「パターンの書き方」)。必須 |
| `judgment` | 判定。`deletable`・`review`・`keep` のどれか。必須 |
| `reason` | 判定の理由。一覧の表の「理由」に示す 1 文。必須 |
| `impact` | 消したときの影響。必須 (`keep` の行でも、消すと何が起きるかを書く) |
| `command` | 消すコマンド (節「消すコマンド」)。`keep` の行は `null`、それ以外の行は必須 |
| `process_names` | そのディレクトリを使うアプリのプロセス名 (`pgrep -x` に渡す名前) の配列。削除のシェルスクリプトは、どれかのプロセスが起動していれば、その項目を消さない (計画の R17・R39)。省略できる (省略は空の配列と同じ) |
| `dedicated_list` | 専用の一覧の種類。`asdf`・`docker` のどれか。この行に一致した項目を指定すると、下の階層の代わりに専用の一覧を作る。省略できる |
| `sources` | 判定とコマンドを確認した文書。`{"url": <URL>, "checked_on": <確認した日 (YYYY-MM-DD)>}` の配列。1 つ以上。必須 |

例:

```json
{
  "pattern": "~/Library/Caches/go-build",
  "judgment": "deletable",
  "reason": "Go のビルドキャッシュ。go のコマンドが、次のビルドで作り直す",
  "impact": "次のビルドとテストが、キャッシュを作り直す分だけ遅くなる",
  "command": {"type": "tool", "args": ["go", "clean", "-cache"], "env": {"GOCACHE": "{path}"}},
  "sources": [{"url": "https://pkg.go.dev/cmd/go#hdr-Build_and_test_caching", "checked_on": "2026-11-25"}]
}
```

## パターンの書き方

- `~/` で始める。`~` はホームディレクトリ (環境変数 `HOME`)。
- 名前を `/` で区切って書く。`*` は、1 つの階層の名前全体に一致する。名前の一部には書けない (`com.google.*` は書けない)。
- `.`・`..`・空の名前 (`//`) は書けない。

パターンは、項目のパスのシンボリックリンクを解決してから照合する。大文字と小文字は区別する (一致しなければ判定なしになり、Claude が調べて判定する)。

## 行を使う項目

行は、パターンに一致したディレクトリと、その下の項目に使う。項目とその親のディレクトリに一致する行が複数あれば、階層の多いパターンの行を使う (計画の KTD5)。

| 行 | パターンに一致したディレクトリ | その下の項目 |
| --- | --- | --- |
| `command` の `type` が `rm` | 行の判定・理由・影響。下の項目と同じく `rm` で消す | 行の判定・理由・影響。その項目を `rm` で消す |
| `command` の `type` が `tool` | 行の判定・理由・影響・コマンド | 残す。ツールのコマンドは一致したディレクトリをまとめて消すので、下の項目だけを消すコマンドが無いため |
| `judgment` が `keep` | 残す | 残す |

同じ深さで同じパスに一致しうる 2 つの行 (`~/Library/Caches/*` と `~/Library/Caches/Google` など) は書かない。どちらの行を使うかが決まらないため。テスト (ファイル `disk-usage-triage/tests/test_judge.py`) が検査する。

## 消すコマンド

`command` は、次のどちらかのオブジェクト。

| `type` | ほかのキー | 消し方 |
| --- | --- | --- |
| `rm` | 無し | 削除のシェルスクリプトが、項目のディレクトリを `rm` で消す (計画の R39 の再確認をしてから) |
| `tool` | `args` (引数の配列。必須)・`env` (環境変数の名前と値のオブジェクト。省略できる) | ツールのコマンドで消す (計画の R15)。ツールのコマンドが無いディレクトリだけを `rm` にする |

`args` の要素と `env` の値には、次の文字列を書ける。削除のシェルスクリプトを作るときに置き換える。要素の一部には書けず、要素全体をこの文字列にする。

| 文字列 | 置き換える値 |
| --- | --- |
| `{path}` | パターンに一致したディレクトリの絶対パス |
| `{name}` | パターンに一致したディレクトリの名前 (パスの最後の部分) |

キャッシュの場所を指定できるツールは、`{path}` で場所を指定する。利用者の設定でキャッシュの場所が変わっていると、指定しないコマンドは、選んだ項目と別の場所を消すため。

`args` は、Claude が書いたコマンドと同じく、許可した実行ファイルとサブコマンドの組 (ファイル `disk-usage-triage/scripts/disk_usage_triage/commands.py` の定数 `ALLOWED`。計画の KTD6) で始める。テストが検査する。

## 判定表に書かないもの

次のものは、判定表に書かず、モジュール `judge` のコードで決める。

- 保護の一覧 (計画の R14)。プラグインを実行している Python の版・作業ディレクトリ・調べるディレクトリのように、実行の環境で決まる場所を含むため。保護の一覧の項目は、判定表より先に「残す」と判定する。
- アプリの worktree の案内 (専用の一覧の種類 `worktree`)。ディレクトリ `.claude/worktrees` は、どの深さにもあり、パターンで書けないため。パスの最後の 2 つの名前が `.claude` と `worktrees` のディレクトリを、この種類にする。

## 行を足すとき

- 消すコマンドを、ツールの文書で確認してから書き、`sources` に文書の URL と確認した日を書く。コマンドは、ツールの版で変わりうるため (計画の節「Risks & Dependencies」)。
- ツールのコマンドの実行ファイルとサブコマンドの組が `commands.py` の定数 `ALLOWED` に無ければ、足す。
- `python3 -m unittest discover -s disk-usage-triage/tests` で、行の様式を検査する。
