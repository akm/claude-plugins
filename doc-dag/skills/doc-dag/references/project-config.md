# プロジェクト固有の設定

このスキルは、リポジトリごとに違う 2 つのことを設定から読む。**設定が無くても動く** — 既定で進み、該当する場面で人間に確認する。

置き場は `.claude/akm-claude-plugins/doc-dag/config.json`。[commit-rules-guard](https://github.com/akm/claude-plugins/tree/main/commit-rules-guard) と同じ流儀で、プラグインは共通の規則を持ち、リポジトリ固有の宣言だけをこのファイルに置く。

## 様式

```json
{
  "frozen_paths": ["docs/brainstorms/", "docs/plans/", "docs/solutions/"],
  "doc_check_command": "make check-docs"
}
```

| キー | 意味 | 未設定のときの扱い |
| --- | --- | --- |
| `frozen_paths` | 書き換えない文書 (過去の記録) のパス接頭辞 | 凍結扱いのパスは無いものとする。ただし手順 5 で正本を過去の記録の側に置く案が出たら、**そこで人間に確認する** |
| `doc_check_command` | ドキュメントの機械検査を走らせるコマンド | 検査を実行せず、**「検査を走らせていない」と明記して報告する** |

## `frozen_paths` — なぜ書き換えない文書があるか

検討の記録・完了した計画・当時の知見は、**その時点の記録として価値がある。** 現行の規約を遡及して適用すると、記録が記録でなくなる。

一方でこのスキルは「重複を参照に変える」修正を行う。**凍結された文書が重複の片側にあると、この手が使えない。** そのときの正しい振る舞いは次のとおり。

- **凍結側を非正本にする案は採らない** (書き換えが必要になるため)。
- **凍結側が正本になっている場合も、参照先にしない。** 現行の文書に記述を移し、そちらを新しい正本にすることを人間に提案する。当時の記録はそのまま残す。

**凍結の有無は機械的に判断できない。** ディレクトリ名から推測せず、設定に書かれたものだけを凍結として扱う。

## `doc_check_command` — なぜ検査が要るか

このスキルの修正は**リンクの張り替えを伴う**。重複を参照に変えるとは、文章をリンクに置き換えることだからである。**リンク切れは書いた本人には見えない** — 相対パスの階層を 1 つ間違えても、文章としては正しく読めてしまう。

検査を走らせない場合、**走らせていないことを報告に明記する。** 「検査で問題が出なかった」と「検査を走らせていない」は別の事実で、混同すると次の読み手が通ったものと誤解する。

## 未設定でも止まらない

設定ファイルが無いことは、**エラーではない**。このスキルの本体 (依存と重複を調べて図にする) は設定なしで完結する。設定は修正フェーズの精度を上げるためのもので、無ければ人間への確認が増えるだけになる。
