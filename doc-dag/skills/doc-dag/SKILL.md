# doc-dag: 文書の依存と重複を DAG にする

文書群を「セクションをノード、依存と重複を辺とするグラフ」として調べ、**同じ事実が 2 箇所で語られて片方だけ古びる構造**を、書き換えの前に見つけて解消する。**修正のたびにレビュー指摘が再生産されるループは、この構造が発生源になる** — 片方を直しても、もう片方が古い事実を語り続けるため。

**これは機械検査ではない。** 重複の同定は意味の判断を含むので、エージェントが読み比べて行い、図で人間に示す。

## 前提知識

- **依存**: セクション A が B の内容を前提にする・リンクする・「正本は B」と参照する関係。向きは **参照元 → 正本**。
- **重複**: 同じ事実 (規則・値・手順・理由づけ) が 2 箇所に書かれている状態。逐語一致に限らず、言い換えも含む。**重複は向きが無いので、そのままではグラフを DAG にできない。**
- **DAG の条件**: 巡回が無い (A→B→A が無い)、かつすべての重複が向き付きの参照に解消されている。

## 手順

1. **対象と設定を確定する**: 引数のパス群。省略時はブランチで変更した `.md` (`git diff --name-only main...HEAD -- '*.md'`) と、それらが相対リンクで直接参照するファイルを加える。あわせて `.claude/akm-claude-plugins/doc-dag/config.json` を読む ([references/project-config.md](references/project-config.md))。**無くてもそのまま進む** — 凍結パスとドキュメント検査が未設定になるだけ。対象と設定の有無を報告してから進む。
2. **セクション単位で調査する**: 各ファイルの見出し (`##` 以下) をセクションとして、次の 2 つを列挙する。
   - **依存**: 相対リンク・「正本は X」「SSOT は X」の参照・内容の前提。リンクは機械的に検出できるが、前提は読んで判断する。
   - **重複**: 同じ事実の再掲。逐語は grep で、言い換えは読み比べで見つける。**どの事実が重複しているかを 1 行で書く** (書けない組は重複と数えない)。
3. **1 枚の mermaid 図にして提示する**: ファイルを subgraph の箱、セクションをその中のノードにする。依存は実線矢印 (参照元 → 正本)、重複は点線 + ラベル `重複`。図は `mermaid-preview` skill の方法で HTML にして人間に見せる (出力はプロジェクト内の `tmp/`、コミットしない)。**`mermaid-preview` は別のプラグインなので、入っていなければ図を出せない** — その場合は mermaid のソースをそのまま提示し、プラグインの導入を案内する。
   - ノードが多すぎて読めないときは、辺に関与しないセクションを箱ごと省き、省いた旨を図の説明に書く。
4. **DAG になっていない箇所を挙げる**: 巡回と、向きの無い重複を列挙し、それぞれにどちらの手 (下記) で解消するかの案を添える。
5. **修正する**: 手は 2 つに限る。
   - **重複を参照に変える**: 同じセクション・ファイルに関する他の依存・参照と**同じ向き**になるように、非正本側の記述を正本へのリンクに置き換える。
   - **正本を明記する**: 記述を残す必要がある場合は、依存先 (正本側) に正本であることを明記し、非正本側に「正本は X」と向きを書く。
   - どちらの側を正本にするかが設計判断になる場合 (どちらにも残す理由がある、正本の置き場自体を変えたい) は、**決めずに選択肢とトレードオフを人間に示す**。
   - **過去の記録は書き換えない** ([references/project-config.md](references/project-config.md) の `frozen_paths`)。過去の記録とは、当時の検討・計画・知見をその時点のまま残す文書のこと。正本が過去の記録の側にあると分かったら、記述を現行の文書へ移して過去の記録を参照元に**しない** (当時の記録はそのまま残し、現行の文書を新しい正本にする) ことを人間に提案する。
6. **修正後に図を作り直して確かめる**: 巡回と向きの無い重複が消えたことを図で示す。修正をコミットする前に、そのリポジトリのドキュメント検査 ([references/project-config.md](references/project-config.md) の `doc_check_command`) を通す。**リンクの張り替えを伴うので、リンク切れの検査を省かない。**

## 原則

- **修正の手を 2 つから増やさない。** 削除・統合・移動はこのスキルの範囲外 — 提案として報告し、実施は人間の指示による。
- **重複の解消は「片方を消す」ではなく「向きを付ける」。** 読みやすさのために要約を残すのは構わない。残すなら正本への参照を添える。
- **図は一時物。** 図の鮮度を維持しない。構造を確かめたいときに、そのたび作る。

## このスキルがしないこと

- **リンク切れ・アンカー切れの検出** — そのリポジトリのドキュメント検査が機械的に行う。このスキルは意味の重複を扱う。
- **文書の品質のレビュー** — 読みやすさ・用語・鮮度などは別の関心事。このスキルは構造 (依存と重複) だけを見る。
- **重複の完全な列挙の保証** — 意味の重複の検出は読みの深さに依存する。見つけた分を図にする。
