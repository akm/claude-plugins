状態遷移に関しては サブディレクトリをやめましょう。 `state-machines-<属性>.yaml` とするのが良さそうです。依存関係の整理で重要なのは参照される側をサブディレクトリに移動することが重要です。今回の例の場合  遷移の元と先の状態 としてdomain.yaml の値を参照することになっていますが、この場合 domain.yaml の値の方がサブドメインに移動するべきです。

 状態遷移は他のドキュメント( 例えば functions.yaml ) から参照されうるので、 state-machines/ を残すと循環参照を生みそうです。

簡単な解決策は提案の通りフラットに同じディレクトリに並べることですが、それでは整理することが難しくなります。必要に応じてサブディレクトリを使えるようにした方が良いです。

規則に手順を含めると、手順が変わったときに規則を変更することになるので避けたいです。規則としては「ツールで生成したファイルの競合を手動で解決せず生成し直す」とだけ書いておけば十分ではないでしょうか。

git については ツールで生成したファイルについては提案の通りで良さそうですが、それ以外のコンフリクトについては、一度そのままコミットして、解決させるコミットを別途追加する方が、 `--remerge-diff` よりもわかりやすいので、この方法も使えるようにしておいてほしいです。
