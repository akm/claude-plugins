Background (from the session that started this one):
Issue #242 は、図を中心にした説明資料を PowerPoint のファイルと Google スライドで作るスキルを、新しいプラグイン `slide-deck` として作る要望。計画は main の `docs/plans/2026-11-09-2343-feat-slide-deck-plugin-plan.md` にあり、実装の単位 U1〜U11 を sub-issue #245〜#255 にした。U1〜U9 と U11 は終わり、slide-deck 0.1.0 は PR #289 で marketplace.json に載って公開された。U10 (#255) は最後の単位で、公開した版の 3 つのスキル (`outline` が構成案、`build` が PowerPoint のファイル、`publish` が Google スライド) を、本物の Google スライドで通して使い、作る・直す・足す・途中から再開する場面で動くことを確認する。スキル `publish` は、コネクタで資料を読んで `build/presentation.json` に書き、サブコマンド `requests` で指示のファイル (20,000 字ごと) を作り、先頭のファイルを revisionId 付きで送ることを繰り返す。作り直す・消す・並べ替える前には利用者の承認を得る。U11 では、項目を指定した読み込み・revisionId 付きの書き込み・マスターの colorScheme の変更が動くことを確認済み。文章の規約は CLAUDE.md に従い、Issue のコメントは wording-guard で検査してから投稿する。

確認すること:
1. スキル `slide-deck:outline` で、見本の題材 (どのプロジェクトの話でもない題材) から構成案を作る。資料のディレクトリは、この作業ツリーの `tmp/` の下にする (git で管理しない)。R1・R4〜R7 の手順を確認する。
2. スキル `slide-deck:build` と `slide-deck:publish` で、作る・直す・足す・途中から再開する、の 4 つの場面を確認する。
3. API の挙動への対処 (KTD14) ごとに、スライドの画像で機能していることを見る。

結果の扱い:
- 場面ごとの結果と、確認できなかったものを、Issue #255 のコメントの下書きにし、wording-guard で検査して利用者に示し、承認を得てから投稿する。コメントに、Google スライドの資料の URL や利用者の個人の情報を書かない。
