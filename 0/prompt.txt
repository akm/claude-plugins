  ## 4. 案
  
  ### 共通の方針
  
  どちらを上流にするかは、各ファイル冒頭の正本の宣言に合わせて決めます。根拠は次の宣言です。
  
  - worker: ワーカーの振る舞いの正本
  - loop-files: 置き場のファイルの契約の正本 (ほかの文書はこれに従う)
  - stops: 図が遷移の正本、決定表が条件と報告の正本で、散文はノード ID で参照する
  - round: ノードと遷移の正本は stops の図
  
  **上流から下流を指す「正本は X」は逆向きの辺になります。** 巡回を作る場合は、(a) の「同じ向きにする」規則に従って、非正本側の言い直しとリンクの両方を消します (参照は反対側から既にある向きのものに任せます)。宣言だけでは向きが決まらない組は、設計判断として選択肢を示します。
  
  ### 案 1 (C1・X01〜X03)
  
  stops の項目の節が「直し方は worker.md から写す。ここでは言い直さない」と既に宣言しています。また、stops から worker への参照が 5 本あるのに対し、逆向きは WK_fix の 2 本だけです。そこで、worker を直し方の正本のまま残し、worker から stops への参照をなくします。
  
  - **1-1. worker「止められたときの直し方」の冒頭の文 (b)**
    - 現: 作業側は RA1 の報告に、止めたものごとに次の直し方を書く (報告の正本は [stops.md](stops.md) の RA1)。
    - 案: **この表が、レビュアの実行を止めたもの (拒否・サンドボックス・権限モードの食い違い・ワーカーの版) ごとの、人間が行う直し方の正本。**
  - **1-2. 同じ節の表の「サンドボックス」の行 (a)**
    - 「足してから再開する手順の正本は [stops.md](stops.md) の RA1。」を消します。
    - 再開の手順は、stops の項目の表が止めたものごとに割り当てています。
  - **1-3. stops「RA1 から再開する手順」の 1 (a)**
    - 現: サンドボックスが止めたときは、止められたのがパスなら設定 `review_loop.sandbox_allow_write` に、ホストなら `review_loop.sandbox_allowed_domains` に足す (設定のファイルは…。キーの正本は…)。
    - 案: サンドボックスが止めたときは、[worker.md](worker.md) の「止められたときの直し方」のサンドボックスの行のとおり設定に足す (設定のファイルは `.claude/akm-claude-plugins/review-triage/config.json`。キーの正本は [project-config.md](../../review-triage/references/project-config.md) の「`review_loop`」)。
  - **1-4. stops の項目の節の「足す値の候補」(a)**
    - 現: サンドボックスと関係の無いエラー (macOS 自身の保護など) なら候補を書かない。
    - 案: 設定では直せないエラー ([worker.md](worker.md) の「止められたときの直し方」のサンドボックスの行) なら候補を書かない。
  
  **宣言を変える選択肢もあります。** stops を直し方の正本にし、表を stops の項目の表へ移して、worker の節は stops を指すリンクにする方法です。報告に書くものは stops の 1 か所にまとまります。ただし直し方は、拒否の規則・サンドボックスの設定・auto モードの実測といった worker の仕組みに依存するので、仕組みを変えるたびに別のファイルを直すことになります。
