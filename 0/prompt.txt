GitHub の Issue の私の使い方のスキルを作りたいです

* リリース Issue ( 次のリリースに向けたメモと、実行の計画と、実行の記録)
* リリース Issue とマイルストーンの対応付け(lappds でやっている方法を改善したい)
* 親Issue と sub-issue の Claude の管理セッションと作業セッションの対応付け
* sub-issue を PR に対応付けて、親 issue に PRマージ計画 を立てる (lappds でやっている方法)
* クローズ条件の明文化 ( 特にPR に対応する Issue )
   * 作成するもの
   * 確認するポイント
* 後で行う作業を Issue に切り出す
   * 他の人の判断や別のPRに依存する部分が後から判明した場合に Issue に切り出す
   * リリース時の作業も同じ


まずは 上記を整理して Issue を作成してください。このセッションは管理セッションとします
