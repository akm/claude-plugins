  ### 4. 計画で技術的に決めてよいもの
  
  - **origin の検査:** 設定値そのものを読み (0-B)、URL を正規化する。対象は SSH の scp 形式・`ssh://`・https・末尾の `.git` と `/`・大文字小文字。参考になる実装は、ファイル `issue-dispatch/scripts/issue_dispatch/repo.py` の正規表現 `_SCP_RE` と `_URL_RE`。プラグインの外からは import できないので、写して使う。
  - **fetch と読み取り:**
    - `git fetch origin +refs/heads/main:refs/remotes/origin/main` のように refspec を明示する
    - SHA を 1 回だけ解決し、`git show <SHA>:<source.path>/.claude-plugin/plugin.json` で読む
    - パスはプラグインの名前ではなく `source.path` から作る
    - 各要素の `source` が git-subdir であること、url が akm/claude-plugins であること、ref が main であること、marketplace.json の `name` を検査する
  - **検査の順序:** 対象のプラグインすべての版を、変更を伴う claude コマンドを実行する前に検査する。処理の順は marketplace.json の並びにする。
  - **install と update:** `--json` を付けて実行し、終了コードで成否を判定する。失敗したら `message` を標準エラー出力に出す。成功するたびに `claude plugin list --json` を読み直す。
  - **git に渡す環境変数:** 消すのは GIT_DIR・GIT_WORK_TREE・GIT_INDEX_FILE などだけにする。issue-dispatch の関数 `_clean_env` は `GIT_*` をすべて消すが、そのまま写すと、テストの安全策の `GIT_ALLOW_PROTOCOL` と `GIT_CONFIG_GLOBAL` まで消えてしまう。
  - **Makefile:**
    - スクリプトのパスは Makefile の場所から作り、リポジトリのルートは cwd (または引数) で受ける。こうすると、テストで一時的なリポジトリを指せる
    - GNU Make 3.81 で動く書き方にする
    - `make help` の説明は日本語で書く
  - **Python の版:** 動かす版の下限を決めて書く。CI は 3.11、macOS の標準は 3.9.6。
