2. Key Technical Concepts:
   - review-loop architecture:
     - The work side (skill) and the worker (bash script running `claude -p`) exchange files in the loop dir (`loop.yaml`, `worker.yaml` with mtime heartbeat, `delivered-<id>.yaml` markers, `review-request-<id>.md`, `review-<id>.yaml`, `<id>.log`, `end`).
     - Background wait script with exit codes 0/124/other.
     - Re-entry procedure; stop nodes RA1–RA3; RG0/RL1 replace G0/L1 of loop-flow.md.
   - Claude Code `-p` permissions:
     - `--permission-mode auto` (classifier). In `-p`, repeated blocks mean the action is skipped and the run continues. If auto is unavailable, it silently falls back to manual. `init.permissionMode` in stream-json shows the actual mode.
     - Safety checks (e.g. `Contains simple_expansion`, `brace with quote character`, env-prefix `requires approval`, rm/grep/redirect outside the working dir) deny even allowed commands in default mode.
   - Sandbox (macOS Seatbelt):
     - Keys: `sandbox.enabled`, `sandbox.autoAllowBashIfSandboxed`, `sandbox.allowUnsandboxedCommands: false` (in the binary but undocumented), `sandbox.filesystem.allowWrite`.
     - It confines Bash writes only. Writes to the working dir and `/private/tmp` are allowed; home writes are blocked with `operation not permitted`.
     - Blocks are not counted in `permission_denials`, and there is no sandbox info in the log.
     - The Bash tool parameter `dangerouslyDisableSandbox` lets a reviewer retry outside the sandbox, and auto mode allows it unless `allowUnsandboxedCommands: false`.
     - Network restriction (`sandbox.network.allowedDomains` / `strictAllowlist`) did NOT take effect via `--settings` in `-p`; cause unknown.
   - Deny rules (`--disallowedTools 'Edit(~/**)' 'Bash(git push:*)' 'Bash(curl:*)'`) take precedence over the auto classifier and over user-stated intent. They apply to sub-agents, and sub-agent denials are counted in the top-level `result.permission_denials`.
   - Disposable worktree via `git clone --shared` into tmp. `git worktree` puts the gitdir under home, so sandboxed git writes fail.
   - `go test` needs `sandbox.filesystem.allowWrite: ["~/Library/Caches/go-build"]`.
   - bash 3.2 compatibility: `${arr[@]+"${arr[@]}"}` for empty arrays; `${var}` bracing before Japanese characters; process groups via `python3 os.setpgid`; watchdog/heartbeat subshells check `worker_alive` (ps stat, zombie counts as dead).
