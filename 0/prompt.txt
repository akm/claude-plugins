2. Key Technical Concepts:
   - The review-loop worker (bash, macOS /bin/bash 3.2 compatible). Per round it:
     - Creates a workspace `<TMPDIR real>/review-loop-<loop id>-<sha256[:8] of loop dir real path>/`.
     - Makes a `tree/` clone: `git clone --shared --no-checkout`, removes the remote, fetches refs/heads, refs/remotes and refs/tags with `--update-head-ok`, then checks out the full SHA detached. A submodule causes the round to fail.
     - Writes a request copy with the output path, repo_dir and `- 作業ツリーの扱い: 使い捨て` replaced.
     - Runs the reviewer `claude -p` with:
       - `--permission-mode auto` (default)
       - `--settings` with one JSON:
         - sandbox.enabled, autoAllowBashIfSandboxed, allowUnsandboxedCommands false, failIfUnavailable true
         - filesystem.allowWrite = workspace + `--sandbox-allow-write`
         - network.strictAllowlist true, network.allowedDomains = `--sandbox-allowed-domain`
         - autoMemoryEnabled false
         - enabledPlugins merged from the extra args
       - `--strict-mcp-config`
       - allowedTools = the read-only defaults + `Edit(//<workspace>/review-<id>.yaml)`
       - disallowedTools = AskUserQuestion, `Edit(~/**)`, `Edit(//repo/**)`, `Edit(//loop dir/**)`, the clone's .claude/.git/.mcp.json, and `Bash(git push:*)`
     - Finishes the round in this order: stop leftover processes by cwd (lsof on macOS, /proc on Linux) → read the log → checks → copy the result (1 MiB cap, O_NOFOLLOW) → remove the workspace (add rwx first; git is not used) → write the marker.
     - Measures the timeout from request pickup, including preparation (`run_prep` process groups, watchdog sends USR1 repeatedly).
     - Signal handling by `PHASE` (prep, review, finish). Signals during finish are deferred.
     - Startup cleanup right after check 1 (by cwd, from `worker.yaml` `workspace`).
     - Start checks 1–15:
       - macOS via uname
       - TMPDIR present and outside home and the repo
       - the repo is not under /private/tmp/claude-<uid>
       - no special characters in paths
       - allowWrite values are not home, the repo, or the loop dir, nor their ancestors
       - extra args limited to `--plugin-dir` and `--settings` with enabledPlugins only
       - user settings have no `sandbox.excludedCommands`
       - WebFetch(domain:) notice (check 15)
     - Log reading:
       - the effective permissionMode from the first top-level init line
       - sandbox_blocked = Bash tool_results with is_error set and text containing "operation not permitted" (case-insensitive) or `<sandbox_violations>`, including sub-agent lines
     - Marker keys: worker_version, permission_mode{specified, effective}, sandbox_blocked{count, calls[{command, message}]}.
