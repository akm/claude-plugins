# mermaid-preview: mermaid 図の HTML プレビュー

mermaid の図を人間に見せるための HTML を生成して開く。**この文書が、mermaid を HTML で表示する方法の検証済み知見の正本** — 他のスキル・文書はここを参照し、再掲しない。

## 検証済みの制約

実際に作って確かめた知見 (2026-08-29 の検証)。理由ごと守る。

| 制約 | 理由 |
| --- | --- |
| **出力先はプロジェクトフォルダ内の `tmp/`** | スクラッチパッド (`/private/tmp/...`) に置くと in-app ブラウザで静的スナップショット扱いになり、スクリプトが実行されず図がテキストのまま見える。`tmp/` が無ければ作り、`.gitignore` されていることを確認する (されていなければ `.gitignore` に追加する) |
| **mermaid は CDN 参照** | ローカルからしか開かないので、同梱 (約 3.4MB) は負担に見合わない。CDN 版とローカル版はバイト単位で同一だった |
| **読み込み失敗時のフォールバックを入れる** | ネットワーク不通か表示方法の問題かを画面上で切り分けられるようにする。無いと原因を取り違える |
| **subgraph は、テーマ変数を使うページでは使わない** | mermaid が subgraph の背景を `#mermaid-<id>` 付きの CSS で当てるため、ページ側のテーマ変数が届かず、ライトテーマで暗い箱が残る。そのようなページでは囲みの代わりにノードの色分けで構造を示す。**テーマ変数を持たない素の [template.html](template.html) では問題なく描画される** (2026-08-30 実測) |
| **`mermaid.min.js` は `eval` / `new Function` の中では動かない** | トップレベルの `var` を末尾で `globalThis` 経由で読む作りのため。`<script>` 要素として読み込む (テンプレートはそうなっている) |

## 手順

1. **図のソースを決める**: 引数の mermaid 記法、または依頼元のスキル・文書から受け取る。テーマ変数を使うページに埋め込む場合のみ、subgraph をノードの色分け (`style <id> fill:...`) に置き換える (上の制約)。
2. **HTML を生成する**: [template.html](template.html) をコピーし、プレースホルダを置換する。
   - `__TITLE__` — ページと見出しのタイトル
   - `__NOTE__` — 図の説明 (凡例など。不要なら空にする)
   - `__DIAGRAM__` — mermaid 記法のソース。図が複数あるときは `<pre class="mermaid">` ブロックごと増やす
   - 出力先はプロジェクトルートの `tmp/` 配下。ファイル名は ASCII (例: `tmp/doc-dag-review-triage.html`)
3. **ブラウザで開く**: 生成したファイルの絶対パスを `file://` で開いて提示する。**ブラウザを開けない実行経路 (headless・cron など) では、生成したパスを案内して終了する** — 図の生成までがこのスキルの成果で、表示は環境があるときだけ行う。
4. **描画を確かめる**: 図が描画されていること (テキストのままでないこと) を確認してから人間に案内する。フォールバック文言が出ていたら、CDN への到達を疑う。

## 後片付け

- 生成した HTML は一時物。**コミットしない** (`tmp/` は `.gitignore` に入れておく)。
- 同じ目的で作り直すときは同じファイル名に上書きし、ファイルを増やさない。

## このスキルがしないこと

- **図の内容の設計** — 何をどう図にするかは依頼元 (人間・他のスキル) が決める。
- **Markdown への図の埋め込み** — 文書に残す図は Markdown の ```` ```mermaid ```` フェンスで書く。このスキルはブラウザで見せる一時的な提示だけを担う。


ARGUMENTS: doc-dag の結果 (review-triage の変更した文書群)。図は 2 枚: 「修正前」(点線 = 向きの無い重複) と「修正後」(重複を参照の向きに解消)。
