# 直す範囲と、書き換えないもの

このスキルは**これから外へ出す文章**を対象にする。同じファイルの中にあっても、対象になる記述とならない記述がある。

## 直すのは、今回の変更で持ち込んだ文章

境目は「誰が書いたか」ではなく、**今回の変更で持ち込んだかどうか**で決める。コマンド `git blame` で書き手を調べるのではなく、差分の範囲で判断する。

| 対象の指定 | 直す範囲 | 直さずに報告する範囲 |
| --- | --- | --- |
| 引数でパスを指定 | そのファイルのうち、ブランチの差分と未コミットの変更に含まれる行。新しく作ったファイルは全体 | 差分の外にある記述 |
| 引数なし | ブランチの差分と未コミットの変更に含まれる行。新しく作ったファイルは全体 | 対象のファイルの、差分の外にある記述 |
| 下書きを渡された | 下書き全体 | 下書きが引用しているもの (下記) |

**人間が「このファイル全体を直して」と明示したときは、その指定に従う。** ただしそれは既存の文書の一括修正という別の作業であって、このスキルのデフォルトの動きではない。

## 書き換えないもの 3 種

### 1. 引用

他の文書の原文を引いている箇所は、原文のまま残す。書き換えると、読み手が原文を探しても見つからない。

引用の目印は設定キー `quote_markers` (ファイル [wording-guard/skills/wording-guard/references/project-config.md](project-config.md))。デフォルトは引用ブロック (`> ` で始まる行) とコードブロック。**目印が付いていない引用もある** — 鉤括弧で原文を引いている文は、読んで判断する。

### 2. 他の人が既に書いた文章

今回の変更で持ち込んだものでなければ、同じ種類に当てはまっても直さない。

**これが 3 種の中でいちばん難しい。** レビューコメントを書くとき、レビュー対象のコードのコメントに同じ表現があると、直したくなる。しかしそれがブランチ `origin/main` の側にも同じだけあるなら、その変更が持ち込んだものではない。見つけたことを報告し、直すかどうかは人間が決める。

**規範文書が使っていることは、自分が使ってよい理由にならない。** 規約や手順書の側に「検査が落ちる」「テストが走る」があっても、これから書く文章では言い換える。規範文書の側を直すのは別の作業である。

### 3. 過去の記録

検討の記録・完了した計画・当時の知見・レビュー指摘を逐語で引用した記録は直さない。

**なぜ書き換えないかと、設定が無いときにどうするかの正本は [project-config.md](project-config.md) の「`frozen_paths` — なぜ書き換えない文書があるか」。** 設定の書き方は同じファイルの「様式」にある。
