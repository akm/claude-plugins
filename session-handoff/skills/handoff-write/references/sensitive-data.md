# 機密の扱い

**引き継ぎ文に機密の値を書かない。** GitHub の Issue と PR のコメントは、公開リポジトリなら全世界から読め、編集しても履歴が残り、回収できない。ローカルファイルに保存する場合も同じ規則に従う — 後から同じ内容を GitHub に投稿し直すことがあり、そのときに改めて見直すとは限らないため。

## 何を書かないか

**次の種類の値は書かない。これは代表例で、列挙がすべてではない。**

- トークン・パスワード・API キー・Webhook の URL
- ファイル `.env` の中身、鍵ファイルの中身
- 会話の中で人間が貼った資格情報

**上に当てはまらなくても、それを知った人が何かをできてしまう値は書かない。** 内部 IP、社内システムの URL、個人名など。**迷ったら書かない。**

**リポジトリの `.gitignore` が保護しているファイルの中身は、引き継ぎ文にも書かない。** コミットしないものを、コメントで外へ出さない。

## 代わりに何を書くか

**値の代わりに、値の入手先を書く。** 新しいセッションはその値が要るから引き継ぎ文を読む。

```
API キーは環境変数 `FOO_API_KEY` に設定済み (値は書かない。未設定なら人間に尋ねる)
```

**値の一部を残さない。** 末尾 4 桁や接頭辞を残す書き方は、残したぶんが漏れる。

**機密でない値まで消さない。** リソースの ID・ファイル名・有効期限のような、知っても何もできない値は、引き継ぎに必要なら書く。

## 投稿前の確認

**GitHub への投稿は、毎回、投稿の前に人間に確認する。** 確認では次の 3 つを示す。

1. 保存先と、そう決めた根拠
2. 本文を書いたファイルのパス (人間が全文を読めるように)
3. 機密に当たりうる値を書かなかった場合は、何を書かなかったか

ローカルファイルへの保存は確認を要さない。
