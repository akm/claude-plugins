# 再開前に確かめる項目

引き継ぎ文の冒頭の表には、書いた時点のリポジトリの状態が入っている。再開の前に、現在の状態と比べる。

```bash
git remote get-url origin
git branch --show-current
git rev-parse --short HEAD
git status --porcelain
git merge-base --is-ancestor <引き継ぎ文の HEAD> HEAD   # 現在の HEAD が、引き継ぎ文の HEAD の子孫か
```

## 判定

| 状況 | 扱い |
| --- | --- |
| リポジトリ・ブランチ・HEAD・未コミットの変更がすべて一致 | そのまま進む |
| ブランチは同じで、HEAD が引き継ぎ文の HEAD から進んでいる | `git log --oneline <引き継ぎ文の HEAD>..HEAD` を要約して示し、進む。引き継ぎ文の「次にやること」が、進んだコミットで済んでいないかを確かめる |
| 引き継ぎ文には未コミットの変更が無く、現在はある | 変更の一覧を示し、進む。引き継いだ後に人間が手を入れた可能性が高い |
| **リポジトリが違う** | **止まる。** 別のリポジトリで開いている |
| **ブランチが違う** | **止まる。** 現在のブランチと引き継ぎ文のブランチを示し、切り替えてよいかを人間に尋ねる。未コミットの変更があるときに、確認なしでブランチを切り替えない |
| **引き継ぎ文に書かれた未コミットの変更が、現在は無い** | **止まる。** 別の作業ツリー (worktree) か別のマシンで開いている、または変更が失われた可能性がある。コミット済みになっていないかを `git log` で確かめ、結果を添えて報告する |
| **現在の HEAD が、引き継ぎ文の HEAD の子孫ではない** | **止まる。** 履歴が書き換えられた (rebase、reset など) か、別の系統にいる。両方の HEAD を示す |
| git のリポジトリの外で書かれた引き継ぎ文 (表の値が「なし」) | 突き合わせを省き、進む |

**止まるときは、食い違いの内容と、考えられる原因と、人間に決めてほしいことを示す。** 「状態が違います」だけでは、人間が次に何をすればよいか分からない。

## 突き合わせの対象にしないもの

- **未 push のコミットの数。** 引き継いだ後に push しただけで変わる
- **作成日時からの経過時間。** 古い引き継ぎ文でも、状態が一致していれば再開できる。ただし 1 週間以上前のものは、その旨を理解の提示に 1 行添える
